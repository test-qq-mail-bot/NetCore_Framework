# 程序逻辑

本文说明 NetCore Framework 启动、插件加载、请求处理的核心流程，便于二次开发与排障。

## 1. 整体架构

```
main.py
  └─ core.framework.create_app()
       ├─ 模块导入期：_extract_bundled_resources()  // 单文件打包后提取资源
       ├─ FastAPI(app, lifespan)
       │    ├─ 中间件：security_middleware（IP 黑白名单 + 审计客户端 IP）
       │    ├─ 中间件：ops_nocache_middleware（opstoolbox 禁缓存）
       │    ├─ 注册核心路由（/api 前缀）：auth / security / notify / audit / system / plugins
       │    ├─ 挂载前端静态资源 /assets
       │    ├─ 挂载 /wiki 静态资源
       │    ├─ 挂载各插件 frontend/ → /plugin-assets/<name>/
       │    ├─ /api/plugins/frontend-manifest  // 返回插件 JS 清单
       │    └─ SPA 兜底：404 回退 index.html
       └─ lifespan 启动时：
            bootstrap() → 加载插件 pm.load_all() → pm.mount_routes(app)
```

## 2. 启动与资源提取

`main.py` 调用 `create_app()`。在 `create_app` 之前，模块导入期会执行 `_extract_bundled_resources()`：

- 单文件打包（PyInstaller `--onefile`）运行时，资源被解压到临时目录 `_MEIPASS`。
- 框架将 `frontend/`、`wiki/`、`plugins/` 以**递归合并拷贝**方式提取到程序目录 `BASE_DIR`。
- 关键保护：跳过 `data/`、`logs/`、`__pycache__` 子目录（递归生效），因此升级/重启不会清空插件的 SQLite 数据库（v40 修复的「设备重启丢失数据」根因）。
- 升级场景还会清理插件 `frontend/` 中已被新版本移除的孤儿 `.js`，不影响运行时数据。

`BASE_DIR` 的确定：

- 打包后（`sys.frozen`）：`sys.executable` 所在目录（避免从不同工作目录启动导致数据漂移）。
- 开发模式：`项目根目录`（即 `NetCore-Framework-github/`）。

## 3. 插件发现与加载

`core.plugin_manager.PluginManager`：

1. `discover()`：扫描 `plugins/` 下所有包含 `plugin.py` 的子目录，返回插件名列表。
2. `load_all()`：读取 `user_config.yaml` 的 `plugins.disabled` 列表，跳过被禁用的插件；对其余插件调用 `_load_plugin(name)`。
3. `_load_plugin`：
   - `importlib.import_module("plugins.<name>.plugin")`
   - `_find_plugin_class`：在模块中查找 `BasePlugin` 的子类（非基类本身）。
   - 读取插件配置：`plugins/<name>/config/config.yaml` 或 `plugins/<name>/config.yaml`。
   - 实例化并调用 `on_load()`；获取 `get_routes()`（APIRouter）与 `get_menus()`。
   - 单插件加载失败仅记录错误，不影响其他插件（故障隔离）。
4. `mount_routes(app)`：将各插件的 `APIRouter` 挂到 FastAPI；通过 `id(router)` 集合**幂等防重**，避免重复注册。

> 运行期启用/禁用插件（`/api/plugins/{name}/toggle`）后必须调用 `mount_new_routes()` 补挂路由，否则会出现「菜单出现但 API 404」。

## 4. 插件契约

插件需继承 `core.plugins.base_plugin.BasePlugin` 并实现：

| 方法 | 必填 | 说明 |
| --- | --- | --- |
| `get_metadata()` | 是 | 返回 `{name, version, description, author}` |
| `on_load()` | 是 | 初始化（建库、加载配置），返回 `True/False` |
| `get_routes()` | 是 | 返回 `APIRouter(prefix="/api/<name>")` 或 `None` |
| `get_menus()` | 是 | 返回菜单项列表（左侧导航） |
| `on_unload()` | 否 | 优雅关闭（如关闭调度器），最长等待 10 秒 |

## 5. 请求处理管线

1. 所有请求经 `security_middleware`：
   - 记录客户端 IP 到上下文（供审计使用）。
   - 登录 / 静态资源 / 健康检查等白名单路径跳过 IP 校验。
   - 命中黑名单返回 `404`（隐藏后台存在）。
2. 业务路由通过 `Depends(get_current_user)` 校验 JWT；未带合法 token 返回 401。
3. 写操作建议调用 `core.audit.audit_log(action, detail, result, username)` 记录审计。
4. 前端 `axios` 拦截器自动携带 `Authorization: Bearer <token>`，并定时 `heartbeat` 续期会话。

## 6. 前端插件机制

- 插件将页面脚本放在 `plugins/<name>/frontend/*.js`。
- 脚本通过 `window.NC.registerPage(id, {template, data, methods}, title, path)` 自注册页面（路径 → id 自动推导）。
- 框架 `/api/plugins/frontend-manifest` 扫描目录返回 JS 清单，前端动态注入 `<script>`。
- 前端下载 / 报表等二进制通过 `http.get(blob)` + `createObjectURL` 处理（因为 `/plugin-assets/` 不鉴权）。

## 7. 配置加载与缓存

`core.config_loader`：

- 首次启动调用 `bootstrap()` 生成默认配置（带中文注释渲染，而非 `yaml.safe_dump`，避免注释丢失）。
- `get_user_config()` 等带缓存；**仅当读取到非空内容才缓存**，防止 bootstrap 早期空配置污染。
- `save_user_config()` 写盘时保留中文注释。
- 内置版本号硬编码于 `SYSTEM_VERSION`（如 `20260824-V2`），且不随用户自定义 name/version 变化（用于核对程序新旧）。

## 8. HTTPS 与证书

- `https.enabled=true` 时默认自动生成自签名证书（`data/certs/`）。
- 可在「基础设置」上传自定义证书（`.crt/.pem` + `.key`），PEM 文本写入 `user_config.yaml` 的 `https.cert_content/key_content`，重启生效。
- 反向协议跳转：误用 http/https 访问会自动 307 跳转到主服务端口（需重启生效）。
- SAN 证书需含访问 IP：HTTPS 工具会枚举网卡 IP 并支持 `https.domain` 显式配置。
