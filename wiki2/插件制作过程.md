# 插件制作过程（从零开发一个插件）

本文以「内置 wiki_docs 插件」为参考，说明如何为 NetCore Framework 开发一个新插件。

## 1. 目录结构

在 `plugins/<name>/` 下创建：

```
plugins/<name>/
├── plugin.py            # 插件入口，继承 BasePlugin
├── config.yaml          # 插件默认配置（可选，放 config/ 子目录或根目录）
├── routes/              # 接口路由（可选，可放在 plugin.py 内）
│   ├── __init__.py
│   └── xxx.py
├── db/                  # 数据访问层（可选，SQLite 等）
├── engine/              # 业务引擎（可选）
├── tools/ clients/      # 工具 / 客户端实现（可选）
└── frontend/            # 前端页面脚本（*.js）
    └── index.js
```

## 2. 实现 plugin.py

```python
from typing import Dict, List, Optional
from fastapi import APIRouter, Depends
from core.auth import get_current_user
from core.logger import get_logger
from plugins.base_plugin import BasePlugin

logger = get_logger()

class MyPlugin(BasePlugin):
    def get_metadata(self) -> Dict[str, str]:
        return {
            "name": "myplugin",
            "version": "20260825-V1",
            "description": "示例插件",
            "author": "Your Name",
        }

    def on_load(self) -> bool:
        # 初始化：建库、加载配置、启动调度器等
        logger.info("MyPlugin 加载完成")
        return True

    def get_routes(self) -> Optional[APIRouter]:
        router = APIRouter(prefix="/api/myplugin")   # 前缀建议 /api/<name>
        @router.get("/hello")
        async def hello(user: str = Depends(get_current_user)):
            return {"msg": "hello"}
        return router

    def get_menus(self) -> List[Dict]:
        return [{
            "id": "myplugin",
            "label": "示例插件",
            "icon": "plugin",
            "children": [
                {"id": "myplugin_home", "label": "首页", "icon": "dashboard",
                 "path": "/myplugin/home"},
            ],
        }]

    def on_unload(self):
        # 关闭资源（调度器、连接池等）
        pass
```

要点：

- `get_metadata()["name"]` 必须与目录名一致。
- 路由前缀统一 `/api/<name>`，避免与核心或其他插件冲突。
- 写操作建议 `audit_log("action", "detail", "success", username=user)`。
- 依赖 `core.audit` / `core.auth.get_current_user` / `core.config_loader` 等标准接口。

## 3. 前端页面自注册

在 `frontend/*.js` 中：

```js
window.NC.registerPage(
  "myplugin_home",                       // 页面 id（与菜单 id 对应）
  {
    template: `<div>示例：{{ message }}</div>`,
    data() { return { message: "hello" } },
    methods: {}
  },
  "示例首页",                            // 菜单标题
  "/myplugin/home"                      // 前端路由 path（与菜单 path 一致）
);
```

- 框架扫描 `plugins/<name>/frontend/*.js`，经 `/api/plugins/frontend-manifest` 暴露为 `/plugin-assets/<name>/<file>.js?v=<mtime>`。
- 二进制下载（报表 / 文件）必须 `http.get(blob)` + `URL.createObjectURL`，因为 `/plugin-assets/` 不鉴权而 `/api/` 鉴权。

## 4. 数据持久化

- 推荐 SQLite，数据库放在插件自身 `data/` 目录（如 `plugins/myplugin/data/my.db`）。
- 使用 `core.config_loader.PLUGINS_DIR / name / "data" / "xxx.db"` 定位路径，保证打包后路径正确。
- `data/` 目录运行时生成，**不进仓库**（已在 `.gitignore` 排除）。

## 5. 依赖声明

- 插件仓库自带 `requirements.txt`，仅列本插件需要的依赖（全部 `==` 精确锁定）。
- 主框架 `requirements.txt` 已包含全部插件依赖，部署框架时无需重复安装。

## 6. 部署与调试

1. 将 `plugins/<name>/` 整体放入框架 `plugins/`。
2. 开发模式 `python main.py` 启动即可加载；Web 后台「插件列表」可热重启 / 临时禁用。
3. 如需单独发布：建独立仓库，仅含源码（排除 `data/`、缓存、二进制），用户下载后放入 `plugins/` 即可。

## 7. 鉴权与审计约定

- 所有 `/api/<name>/*` 接口内部通过 `Depends(get_current_user)` 鉴权，未带合法 JWT 返回 401。
- 公开接口（如健康检查）可不加依赖，但业务接口必须鉴权。
- 关键写操作统一 `audit_log` 记录，便于「日志中心」追溯。

## 8. 常见坑

- 路由注册顺序：FastAPI 按注册顺序匹配，`/api/<name>/items/{id}` 必须注册在 `/api/<name>/items/batch-xxx` 之后（路径更具体的放前面），否则被通配路由截走。
- 运行期启用插件后路由若 404，确认框架已调用补挂逻辑（重启可解）。
- 前端模板：不要用 `this.$set`；绑定以 `.` 开头的字符串必须加引号；修饰符事件需配 handler。
