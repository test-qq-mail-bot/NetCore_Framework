# 教程：部署、配置与构建

## 1. 环境要求

- Python 3.13（开发模式）或已构建的单文件可执行程序（无需 Python 环境）。
- 操作系统：Windows / Linux（x64）。
- 网络：默认监听 `0.0.0.0:8080`，首次启动自动生成配置与自签名证书。

## 2. 开发模式运行

```bash
pip install -r requirements.txt
python main.py
```

启动后访问 http://localhost:8080 。默认账号 `admin` / `Admin@123!`。

> 若端口 8080 被占用，框架会自动顺延到 +1 ~ +20 之间的可用端口，并在控制台提示实际访问地址。

## 3. 首次启动做了什么

`main.py` → `core.framework.create_app()` → 生命周期 `lifespan`：

1. `bootstrap()`：创建 `config/`、`data/`、`logs/`、`plugins/`、`frontend/`、`wiki/` 目录；生成默认配置（`core.yaml` / `user_config.yaml` / `security.yaml` / `notify.yaml`）。
2. 默认密码哈希写入 `user_config.yaml`（`Admin@123!`）。
3. 扫描 `plugins/` 目录，将所有含 `plugin.py` 的插件写入 `user_config.yaml` 的 `plugins.detected`。
4. 加载并挂载所有插件路由。

## 4. 基础配置

配置文件位于 `config/`：

| 文件 | 作用 | 是否只读 |
| --- | --- | --- |
| `core.yaml` | 服务监听地址 / 端口、加密密钥、JWT 密钥 | 只读（仅需改 host/port） |
| `user_config.yaml` | 软件名、版本、认证、插件开关、日志、HTTPS、通知频率 | 可读写（Web 后台或手工改） |
| `security.yaml` | 登录失败策略、IP 黑白名单 | 可读写（即时生效） |
| `notify.yaml` | 通知渠道（邮件 / 企业微信 / 钉钉 / 飞书）与模板 | 可读写（即时生效） |

常用配置示例（`user_config.yaml`）：

```yaml
system:
  name: ""                 # 留空使用内置名称
  version: ""
  auto_logout_minutes: 5   # 无操作自动退出；0=关闭
  timezone: "Asia/Shanghai"
auth:
  totp_enabled: false      # 开启 TOTP 双因素需在 Web 后台绑定
plugins:
  disabled: []             # 例如 [netconfig_guardian] 表示停用该插件
https:
  enabled: true            # 默认启用 HTTPS（自签名）
```

## 5. 安装插件

业务插件为独立仓库，部署步骤：

1. 下载插件仓库，得到 `<插件名>/` 目录（如 `cmdb/`）。
2. 整体复制到框架 `plugins/` 下：`plugins/cmdb/`。
3. 重启框架。框架启动时自动扫描 `plugins/<name>/plugin.py` 并加载（菜单与路由自动注册）。

也可在 Web 后台「系统设置 → 插件列表」中临时启用 / 禁用已存在的插件（持久化到 `user_config.yaml` 的 `plugins.disabled`）。

## 6. 构建单文件可执行

本地构建：

```bash
python build.py --target win      # 产出 dist/netcore-framework.exe
python build.py --target linux    # 产出 dist/netcore-framework
```

产物为 PyInstaller onefile：所有 `frontend/`、`wiki/`、`plugins/` 资源在运行时合并提取到程序所在目录（保留 `data/`、`logs/`、`__pycache__` 等运行时目录，不会覆盖用户数据）。

## 7. 通过 GitHub Actions 发版

1. 给框架仓库打 `v*` 标签（如 `v20260824-V2`）并推送。
2. `push: tags: ['v*']` 触发 `.github/workflows/build.yml`。
3. Windows / Linux runner 并行构建，打 tag 时自动在 Release 上传 `netcore-framework.exe` 与 `netcore-framework`。

> 也可在仓库 Actions 页面手动 `workflow_dispatch` 触发构建（不打 Release）。

## 8. 修改默认密码与开启 TOTP

- 登录后进入「系统设置 → 基础设置」修改密码。
- 在「安全策略」或「基础设置」中开启 TOTP，按页面提示用 Authenticator 扫码绑定；绑定后每次登录需输入动态码。

## 9. 数据备份与迁移

- 用户数据均在程序目录的 `data/`（SQLite 数据库、审计日志、证书）与插件各自的 `data/`（如 `plugins/cmdb/data/cmdb.db`）。
- 迁移只需整体拷贝程序目录；框架重启会基于现有数据继续运行。
