# 07-部署运维

本文档覆盖生产环境部署、HTTPS 证书管理、数据备份恢复、反向代理、监控与日志运维。

---

## 1. 部署形态

### 1.1 EXE 单文件（推荐）

**优势**：无需安装 Python、单文件分发、自带全部依赖。

**步骤**：
1. 将 `netcore-framework.exe` 放入独立部署目录（建议专用账号、非系统盘）
2. 首次运行自动生成 `config/ data/ logs/ plugins/ frontend/ wiki/`
3. 配置防火墙放行端口
4. 用 NSSM / systemd / 计划任务做开机自启

**建议目录结构**：
```
/opt/netcore/                    # Linux 部署目录
├── netcore-framework            # 主程序
├── config/                      # 自动生成
├── data/                        # 自动生成
├── logs/                        # 自动生成
├── plugins/                     # 业务插件
├── frontend/                    # 自动生成
└── wiki/                        # 自动生成
```

### 1.2 源码部署

```bash
git clone <仓库地址> NetCore-Framework
cd NetCore-Framework
uv venv --python 3.13 .venv
uv pip install -r requirements.txt -r requirements-dev.txt --python .venv
python main.py
```

### 1.3 容器部署（Docker）

框架本身不提供 Dockerfile，但可自行构建：

```dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8080
CMD ["python", "main.py"]
```

## 2. 端口与防火墙

### 2.1 端口用途

| 端口 | 用途 | 需要放行 |
| --- | --- | --- |
| 8080（默认） | 主服务（HTTPS 模式对外） | 是 |
| 8081（主+1） | 反向协议跳转监听（HTTP→HTTPS） | 仅启用 auto_redirect 时 |

### 2.2 端口冲突处理

- 配置端口被占用时自动顺延 +1 ~ +20 尝试
- **以控制台打印的实际地址为准**
- 固定端口建议在 `core.yaml → server.port` 显式指定

### 2.3 防火墙配置

**Windows**：
```powershell
netsh advfirewall firewall add rule name="NetCore 8080" dir=in action=allow protocol=tcp localport=8080
netsh advfirewall firewall add rule name="NetCore 8081" dir=in action=allow protocol=tcp localport=8081
```

**Linux**：
```bash
# firewalld
firewall-cmd --permanent --add-port=8080/tcp
firewall-cmd --permanent --add-port=8081/tcp
firewall-cmd --reload

# ufw
ufw allow 8080/tcp
ufw allow 8081/tcp
```

## 3. HTTPS 证书管理

### 3.1 默认自签名

框架首次启动生成自签名证书到 `data/certs/`：
- `cert.pem` — 证书
- `key.pem` — 私钥

**SAN（Subject Alternative Names）自动枚举**：
- 本机所有非回环网卡 IP（如 `192.168.1.100`）
- `localhost`、`127.0.0.1`

浏览器会提示「不安全」——这是正常现象，自签名证书不被浏览器信任。

### 3.2 上传正式证书

Web 后台「基础设置 → HTTPS」上传：
- 证书文件（`.crt` / `.pem`）— PEM 格式，包含完整证书链
- 私钥文件（`.key`）— PEM 格式私钥

上传后 PEM 文本落盘到 `user_config.yaml → https.cert_content/key_content`，重启后生效。

也可手工编辑 `config/user_config.yaml` 直接粘贴 PEM 内容。

### 3.3 SAN 校验修复

远程客户端访问报证书域名不匹配时：
1. 在 `user_config.yaml → https.domain` 填写访问 IP/域名（逗号分隔）
2. 重启程序，自签名证书重新生成并包含这些地址

```yaml
https:
  domain: "192.168.1.100,myserver.local,10.0.0.5"
```

### 3.4 关闭 HTTPS

如果你有反向代理（Nginx/Caddy）在前端做 TLS：

```yaml
# config/user_config.yaml
https:
  enabled: false
  auto_redirect: false
```

重启后框架以纯 HTTP 运行。**建议同时清空 `redirect_port`**。

## 4. 数据与备份

### 4.1 数据位置

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 配置 | `config/*.yaml` | 四份 YAML，含密码哈希/密钥/名单/通知凭据 |
| 业务数据库 | `data/` 与 `plugins/<name>/data/` | SQLite，随写随落盘 |
| 审计日志 | `data/logs/audit/audit-YYYYMMDD.log` | JSONL 按天 |
| 运行日志 | `logs/YYYYMMDD-netcore.log` | 按天+大小滚动 |
| 证书 | `data/certs/` | 自签名或自定义 |
| JWT 密钥 | `data/.secret_key` | 进程内缓存，持久化到此文件 |

### 4.2 备份策略

**推荐备份目录**：
```bash
# 定期备份（如每日 cron）
tar czf netcore-backup-$(date +%Y%m%d).tar.gz \
    config/ \
    data/ \
    plugins/*/data/
```

**必须备份**：
- `config/` — 全部配置（含密码哈希、密钥、名单、通知凭据）
- `data/` — 数据库、证书、审计日志
- `plugins/<name>/data/` — 插件数据库

**可选备份**：
- `logs/` — 运行日志（排查用，非必须）
- `frontend/` — 如有自定义前端修改

### 4.3 恢复

1. 停止程序
2. 将备份的 `config/`、`data/`、`plugins/<name>/data/` 覆盖回原位
3. 启动程序

### 4.4 升级安全机制

EXE 启动采用「合并提取」：
- **覆盖写入**：`frontend/`、`wiki/`、`plugins/` 中的代码资源
- **不删除/不覆盖**：`data/`、`logs/`、`__pycache__`（递归生效）
- **插件数据库跨版本保留**
- **孤儿前端 JS 清理**：仅对打包内自带插件清理，外部手工部署的插件不受影响

### 4.5 运行时备份（.workbuddy）

每次构建 EXE 前，构建脚本会将部署目录的 `config/`、`data/`、`plugins/` 备份到 `.workbuddy/backup_YYYYMMDD_HHMM_dist_runtime/`。升级失败时可从此目录恢复。

## 5. 反向代理

### 5.1 Nginx

```nginx
server {
    listen 443 ssl;
    server_name myserver.local;

    ssl_certificate     /etc/ssl/certs/myserver.crt;
    ssl_certificate_key /etc/ssl/private/myserver.key;

    location / {
        proxy_pass https://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $remote_addr;  # 必须显式传递
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_ssl_verify off;  # 自签名场景
    }

    # WebSocket 支持（插件网页终端等）
    location /ws/ {
        proxy_pass https://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_ssl_verify off;
    }
}
```

### 5.2 Caddy

```
myserver.local {
    reverse_proxy https://127.0.0.1:8080 {
        transport tls {
            insecure_skip_verify
        }
        header_up X-Real-IP {remote_host}
        header_up X-Forwarded-For {remote_host}
    }
}
```

### 5.3 反代 IP 信任

**关键**：把代理 IP 加入 `user_config.yaml → security.trusted_proxies`，框架才会信任 X-Forwarded-For。

```yaml
security:
  trusted_proxies:
    - "127.0.0.1"      # 本机反代
    - "10.0.0.0/8"     # 内网反代网段
```

**不配置的后果**：所有请求记成代理 IP，失败锁定会误伤全部用户。

## 6. 账户与密钥运维

| 场景 | 操作 |
| --- | --- |
| 忘记密码 | `user_config.yaml → auth.password_plain: "新密码"` 重启（框架自动重置并自删该字段） |
| 密码哈希损坏 | 删除 `auth.password_hash` 行重启，重建为默认密码 `Admin@123!` |
| JWT 密钥轮换 | 替换 `core.yaml → jwt.secret_key`（重启后全员重新登录） |
| TOTP 丢失 | `auth.totp_enabled: false`、`auth.totp_secret: ""` 重启关闭双因素 |
| 回环白名单删除 | 删除后不会自动恢复；重启后本机登录也受失败锁定约束 |

## 7. 日志运维

### 7.1 运行日志

- 位置：`logs/YYYYMMDD-netcore.log`
- 格式：`[YYYY-MM-DD HH:MM:SS] [LEVEL] 消息`
- 滚动：单文件 10MB 轮转，保留 30 份
- DEBUG 级别：含每个请求的明细（方法/路径/状态码/耗时）
- uvicorn 日志已绑定到同一文件/控制台

### 7.2 审计日志

- 位置：`data/logs/audit/audit-YYYYMMDD.log`
- 格式：JSONL（每行一条 JSON）
- 保留：`logging.audit_log_retention_days`（默认 60 天），启动时自动清理
- 内容：登录、登出、安全策略变更、通知测试、插件启停等

### 7.3 日志级别调整

Web 后台「日志中心」可热切换级别（即时生效，重启保持）。

## 8. 健康检查

### 8.1 HTTP 健康端点

```
GET /api/system/health
```

响应：
```json
{
  "status": "ok",
  "time": "2026-08-26T15:36:57Z"
}
```

免认证，适合探针/负载均衡器。

### 8.2 进程监控

建议同时探测：
- 主端口 TCP 可达性
- `/api/system/health` 返回 200
- 进程存在性（PID 文件或 `ps` 检查）

### 8.3 崩溃恢复

推荐用 NSSM（Windows）或 systemd（Linux）管理进程，配置自动重启：

**systemd 示例**：
```ini
[Unit]
Description=NetCore Framework
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/netcore
ExecStart=/opt/netcore/netcore-framework
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```
