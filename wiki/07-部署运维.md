# 04 - 部署运维

本文档面向运维与实施人员，覆盖构建、部署、升级、服务托管、日志与排障。

---

## 1. 构建单文件可执行程序

### 1.1 环境

- Python 3.10+，依赖固定于 `requirements.txt`。
- 兼容 x86/x64 Linux 与 Windows。
- 使用 PyInstaller **onefile** 模式，资源内嵌，首次运行自动提取。

### 1.2 步骤

```bash
# 安装依赖
pip install -r requirements.txt
pip install pyinstaller        # 若未包含

# 执行构建（build.spec 已固化路径与隐藏导入）
pyinstaller build.spec --noconfirm

# 产物：dist/netcore-framework（Windows 为 netcore-framework.exe）
```

> `build.spec` 已包含 `sqlite3` 等隐藏导入及 `frontend/`、`wiki/`、`plugins/` 资源打包，请勿随意改动隐藏导入列表，否则可能出现「No module named 'sqlite3'」等运行期错误。

---

## 2. 部署（复制即用）

1. 将 `dist/netcore-framework`（或 `.exe`）复制到**目标服务器有写入权限的目录**。
2. 直接运行该程序。
3. 程序自动创建 `config/`、`data/`、`plugins/`、`frontend/`、`wiki/` 并生成默认配置。
4. 按控制台提示的端口访问 Web 后台。

> 单文件部署无需安装 Python 或任何运行时依赖。

---

## 3. 端口管理

- 默认端口 **8080**。
- 若 8080 被占用，框架在控制台打印警告并**自动顺延**（8081、8082…）直到可用，然后启动。
- 如需固定端口，修改 `config/core.yaml` 的 `server.port` 并重启。
- 不建议使用 80/443 等特权端口（需相应权限）。

---

## 4. 升级流程

1. 备份：`config/`、`data/`、`plugins/`。
2. 用新版本可执行文件**替换**旧文件。
3. 启动新程序，框架按新配置运行；插件随程序目录加载。
4. 插件升级：备份该插件的 `data/` 与 `config/config.yaml`，替换插件目录后热重启即可。

> 升级不会清空 `config/` 与 `data/`（除非你主动删除）。自定义配置（系统名称/版本、安全策略、通知配置等）会保留。

## 5. 以系统服务托管

### 5.1 Linux（Systemd）

```ini
# /etc/systemd/system/netcore.service
[Unit]
Description=NetCore Framework
After=network.target

[Service]
WorkingDirectory=/opt/netcore
ExecStart=/opt/netcore/netcore-framework
Restart=on-failure
User=netcore

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now netcore
journalctl -u netcore -f   # 查看日志
```

### 5.2 Windows（WinSW 或 sc）

- 使用 WinSW 将 exe 注册为服务；或用 `sc create` 创建服务。
- 注意：服务账户需对程序目录有写入权限。

## 6. 日志与审计

| 类型 | 路径 | 说明 |
|------|------|------|
| 框架日志 | `data/logs/{日期}-netcore.log` | 按天滚动，级别可在「日志中心」临时调整 |
| 审计日志 | `data/logs/audit/audit-{YYYYMMDD}.log` | JSONL，记录登录、插件热重启、通知、安全策略变更等 |
| 插件日志 | `plugins/<插件>/logs/plugin.log` | 插件自身运行日志（如数通配置卫士） |

- 审计日志默认保留 60 天，过期自动清理；也可在「日志中心」手动清理或导出（CSV/JSON）。
- 框架日志保留策略见 `core.yaml` 的 `logging` 段。

## 7. 常见问题速查

| 现象 | 处理 |
|------|------|
| 启动即退出，提示无写入权限 | 更换到有写入权限的目录，或修正目录权限/杀毒软件拦截 |
| 打不开 Web 后台 | 看控制台实际端口（可能已顺延）；确认防火墙放行；尝试 `http://127.0.0.1:<端口>` |
| 登录失败 | 确认账号 `admin` / 密码 `Admin@123!`；TOTP 已绑定时需输入验证码；连续失败会被临时封禁（见 `security.yaml`） |
| 插件加载失败 | 查看框架日志中的插件错误信息；确认插件依赖已安装；用「插件管理」热重启 |
| 通知发不出去 | 在「通知管理」用「测试」按钮验证渠道；检查 `notify.yaml` 中的密码/Webhook 是否填写且已保存 |

更全面的排障见 `09-常见问题FAQ.md`。
