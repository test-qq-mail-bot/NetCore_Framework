# 运维常用工具箱 (OPS Toolbox) 插件开发项目书

> **版本**：20260822-V1（运维工具箱插件版本）  
> **依赖框架**：NetCore Framework 20260821-V1（程序内置版本号）  
> **插件标识**：`ops_toolbox`  
> **设计理念**：基于 NetCore 微核心+插件化架构，提供一套开箱即用的运维常用工具集合，覆盖网络诊断、远程连接/传输、编码/格式/加密、文字处理、TOTP 校验、图片处理、子网计算器八大类，全部以插件形式接入，不改动底层框架。
>
## 〇、使用说明（Quick Start）

> 本插件完全以插件形式接入 NetCore Framework，**不修改底层框架代码**；以下流程均基于打包后的 `netcore-framework.exe` 或直接 `python main.py` 运行。

### 启动与登录
- **启动**：运行 `netcore-framework.exe`（Windows 双击即可；打包后程序目录固定为 exe 所在目录）。首次启动自动生成 `config/`、`data/` 等目录与默认配置，默认管理员账号哈希写入 `config/user_config.yaml` 的 `auth.password_hash`。
- **访问**：浏览器打开 `http://127.0.0.1:8080`。若 8080 被占用，程序自动顺延至 8081…8089，并在控制台与主日志 `data/logs/{日期}-netcore.log` 提示实际端口。
- **登录**：用户名 `admin`，密码 `Admin@123!`（首次启动默认密码，登录后前端会提示修改）。登录凭证在传输前用 `GET /api/system/crypto-key` 返回的 **AES-256-GCM** 密钥加密，服务端 `decrypt_field` 解密后再校验 PBKDF2-SHA256 哈希，明文密码不落网。
- **鉴权**：登录成功返回 JWT（`Authorization: Bearer <token>`）；后续所有 `/api/opstoolbox/*` 请求均需在请求头携带该 Token，缺失或过期返回 **401**。

### 左侧菜单与功能分组
登录后左侧出现「运维常用工具箱」分组，下含四类（含图片处理子项）：
- **A 网络诊断**：连通性探测、路由追踪、端口扫描、HTTP 探测、SSL 证书检查、IP 工具箱、Whois 查询、IP 归属地、Wake-on-LAN、MAC/OUI 厂商、DNS 探测、端口百科、网络测试。
- **B 远程连接 & 传输（3）**：SSH/Telnet 登录、FTP/SFTP客户端、FTP/SFTP/WebDAV/TFTP 服务端。（原「临时 HTTP 服务」已下线，其能力由 WebDAV 服务端覆盖）
- **C 编码 / 格式 / 加密（11）**：Base64/URL/Hex、JSON 格式化、Hash 计算、时间戳转换、密码/UUID 生成、JWT 解析、正则测试、Cron 解析、二维码工具箱、TOTP 工具箱、文字处理。
- **D 图片处理（4 子项）**：图片→Base64、Base64→图片、压缩和格式转换、图片信息。

### 连接配置仅存浏览器（不落服务器）
- 所有连接配置（SSH/FTP/SFTP/WebDAV/Telnet 主机、用户名、端口等）只保存在**浏览器 `localStorage`**（键名以 `opstoolbox_` 前缀分桶），**服务端不存储任何凭据**。
- 「配置管理」页（C 类入口，注册名 `opstoolbox_config`）提供「导出配置」：把全部 `opstoolbox_*` 项打包为 JSON 文件下载；清浏览器缓存后用「导入配置」一键恢复。
- **清空缓存防误触**：点「清空本机配置」弹确认框，**默认焦点在「取消」按钮——按回车 = 取消（不清除）**，只有鼠标点击「清空缓存」才真正删除；ESC 关闭同样不清除。

### B 类临时会话目录隔离（防投毒）
- 打开任一 B 类客户端/服务端功能时，自动在 `<DATA>/ops_toolbox/sessions/<YYYYMMDD_HHMMSS>_<kind>_<随机>/` 创建隔离目录。
- 下载落地文件对服务器**其他本地用户设为只读并去除执行位**（`session.sanitize_file`），属主进程仍可管理，防止投毒/误运行。
- 生命周期：功能面板关闭 / 退出登录 / 服务重启（插件 `on_load`/`on_unload` 调 `session.cleanup_all_stale()`）三重保障清理残留目录。

### 服务端根目录 Web 选择
- FTP/SFTP/WebDAV/TFTP 服务端支持在 Web 界面用「浏览服务器目录」逐级选择根目录（基于 `GET /api/opstoolbox/fs/list`）；也可勾选「临时隔离目录」自动用上述临时会话目录作为根，关闭/登出时自动清除。

> **前端加载顺序约定（改动前必读）**：框架 `/api/plugins/frontend-manifest` 按**文件名字母序**注入脚本。`tools_00_common.js`（"t" 开头）提供 `window.OT` 基座，**任何引用 `OT` 的文件都必须排在它之后**。而 `portinfo_*.js`（"p" 开头）字母序在其之前，因此这两个文件被设计为**零依赖纯数据/页面模块**——只用 `window.NC.registerPage` 原生注册，不得使用 `OT.http` / `OT.reg`，否则启动即报 `OT is undefined`。新增前端文件时请按此规则选择文件名前缀。

### 2.1 故障隔离机制（每个部件单独一个 py 文件）
- **契约**：`tools/<name>.py` 暴露 `TOOL_ID` + `run(params)`；`clients/<name>.py` 暴露原函数（`ssh_batch` 等）；`servers/<name>.py` 暴露 `start_*(...)`。
- **加载**：`registry.load_all()` 用 `importlib.import_module` 逐个导入 `tools/`、`clients/`、`servers/` 下各模块，**每个 import 都包在 try/except 中**：某个文件语法错误 / 运行异常 / 依赖缺失 → 仅记录日志并跳过该组件，其余组件照常工作。
- **分发**：`plugin.py` 不再整体 `import tools/clients/servers`，改为查 `registry.TOOLS`（工具）、`registry.CLIENTS`（客户端）、`registry.SERVERS`（服务端）分发表。某工具未加载时 `/tool/run` 返回"工具不可用（组件未加载）"友好提示，而非 500 崩溃。
- **单点故障隔离**：因为每个组件都是独立文件——`tools/` 下多个 `.py`（单工具模块暴露 `TOOL_ID` + `run(params)`，多工具模块暴露 `TOOLS` 字典；合计 **24 个工具**：网络诊断/连通性探测、远程连接/传输、编码/格式/加密、文字处理、TOTP 校验、图片处理、子网计算器）、`clients/` 下 4 个 `.py`（`ssh_batch` / `telnet_exec` / `ftp_*` / `sftp_*`；WebDAV 客户端已删除）、`servers/` 下 5 个 `.py`（各自 `start_*`，共享 `ServerHandle` 句柄）——并且 `registry._safe_import` 对每个 `importlib.import_module` 都包了 try/except，**单个文件语法错误 / 运行异常 / 依赖缺失，只会禁用那一个组件，其余组件照常工作**。`registry.load_all()` 在插件 `on_load` 时被调用，模块导入即执行一次分发表填充；`registry._load_tools` 同时支持 `TOOL_ID/run` 单工具模块与 `TOOLS` 多工具字典模块。
- 实测：启动日志打印「工具 N 客户端 4 服务端 5」（具体工具数随版本累加），全部加载成功。

- **路由前缀**：`/api/opstoolbox`（由框架 `mount_routes` 自动挂载，零底层改动）。
- **前端注入**：`frontend/` 下 39 个 js 自动注入（20260806-V1 需求⑩ + 20260806-V2 需求⑨：70KB 的 `netcore_client_lib.js` 进一步按功能域拆为 `netcore_lib_base/ip/ipcalc/text/totp` 5 个文件，全局接口不变；共享函数经 `window.OT` 命名空间复用），数字前缀保证经 `/api/plugins/frontend-manifest` 的字母序注入次序与拆分前一致；共享函数经 `window.OT` 命名空间复用，每个工具页面通过 `window.NC.registerPage('opstoolbox_xxx', ...)` 自注册。
- **菜单与路由映射**：菜单 `path: '/opstoolbox/ping'` 等已在 `frontend/app.js` 的 `resolvePageId` 映射表中增加（**这是本次唯一一处框架前端文件改动，与数通卫士接法一致、纯增量、可回退**）。
- **版本号**：插件版本号单点维护于 `plugins/ops_toolbox/routes/common.py` 的 `PLUGIN_VERSION`（当前 `20260809-V7`），`get_metadata()` 与 `/api/opstoolbox/health` 均引用该常量，改一处即可全局生效。底层框架 / 系统版本独立维护于 `core/config_loader.py` 的 `SYSTEM_VERSION`（当前 `20260805-V1`），插件升级不影响框架版本。

## 三、临时会话目录隔离（B 类核心设计）

按需求：远程客户端可登录上传/下载，但落盘后服务器侧对**其他本地用户**设为只读+去执行位，防止投毒/误运行；文件夹生命周期由本插件自管。

- **创建**：打开任一 B 类功能时，在 `<ROOT>/data/ops_toolbox/sessions/<YYYYMMDD_HHMMSS>_<随机>/` 新建隔离目录。
- **只读防投毒**：客户端下载文件落地后，服务器侧用 `chmod`/ACL 将目录对其他本地用户设为只读、去除执行位；Web 只提供"列出+下载"接口，无上传入口（上传由客户端经 FTP/SFTP 协议自行完成，不暴露服务器内部目录）。
- **自动清理**：① 该面板关闭时；② 退出登录时；③ 服务重启时（`on_load`/`on_unload` 调用 `session.cleanup_all_stale()`）三重保障。
- A/C 类不涉及文件传输，不建临时文件夹。

## 四、连接配置不落服务器

按需求：所有连接配置（SSH/FTP/SFTP/WebDAV/Telnet 等）**只存浏览器 `localStorage`**，不写入服务器数据库。

- 每个工具页的配置表单「记住此配置」即写入 `localStorage`（按工具 key 分桶）。
- 提供全局「导出配置（JSON 文件）」「导入配置」按钮，清浏览器缓存后可一键恢复。
- 服务端不保存任何用户连接凭据。
- **清除缓存防误触**：「清空本机配置」按钮点击后弹出 `ElementPlus.ElMessageBox.confirm` 确认框，**默认焦点在「取消」按钮**——按回车 = 取消（不清除），只有**鼠标点击「清空缓存」**才真正删除所有 `opstoolbox_` 前缀的 `localStorage` 项；ESC 关闭同样不清除。

## 五、服务端目录 Web 选择

FTP / SFTP / WebDAV / TFTP 服务端（合并于「FTP/SFTP/WebDAV/TFTP 服务端」单页，按协议单选切换）均支持在 Web 界面选择根目录：

- 「临时隔离目录」**默认开启**，根目录默认即为该隔离目录（关闭/登出时自动清除），进一步隔离。
- 提供「浏览服务器目录」按钮（`GET /api/opstoolbox/fs/list`）：逐级进入/显示当前路径，取消勾选临时隔离后可手动指定持久根目录。

### 5.1 可浏览目录白名单

`GET /api/opstoolbox/fs/list` **不会列出整机磁盘**，只能在白名单根目录内浏览，防止越权遍历服务器文件系统：

- 默认白名单：`plugins/ops_toolbox/data/` 与程序当前工作目录（即 EXE 所在目录）。
- 自定义：启动前设置环境变量 `OPS_TOOLBOX_FS_ALLOWED_ROOTS`，多个路径用英文逗号分隔的**绝对路径**。

```bash
# Windows（cmd）
set OPS_TOOLBOX_FS_ALLOWED_ROOTS=D:\share,E:\backup
netcore-framework.exe

# Linux
export OPS_TOOLBOX_FS_ALLOWED_ROOTS=/srv/share,/data/backup
./netcore-framework
```

不传 `path` 参数时接口直接返回白名单根列表；请求白名单之外的路径会被拒绝。

### 5.2 服务端安全默认值

| 服务端 | 默认行为 | 如何调整 |
|--------|----------|----------|
| FTP / SFTP | 未在表单填写密码时，**不会变成匿名/空密码登录**，而是启用兜底密码 `ops123` | 在启动表单显式填写用户名与密码 |
| TFTP | **默认只读**，客户端上传会被拒绝并提示「TFTP 服务端为只读模式，拒绝写入」 | 勾选「允许写入」后重新启动服务端 |
| 全部服务端 | 根目录默认为临时隔离目录，停止服务/登出时自动清理 | 取消勾选「临时隔离目录」后指定持久根目录 |

> TFTP 协议本身无认证，开放写入等于允许任何能访问该端口的主机上传文件，仅在受控内网短时使用。

## 九、可调用 API 清单（Callable API Reference）

> 统一约定：
> - 除登录/取密钥/前端清单外，所有 `/api/opstoolbox/*` 接口都需 `Authorization: Bearer <token>`（FastAPI 依赖 `get_current_user`）。
> - 鉴权失败返回 **401**。
> - 菜单路径：`/opstoolbox/<tool_id>`（如 `/opstoolbox/ping`）。

### 9.1 框架级接口（任何插件通用）

| Method | Path | 必填参数（类型） | 返回形态 | 需鉴权 |
|---|------|------------------|----------|--------|
| POST | `/api/auth/login` | `username`(str, AES-256-GCM 密文)、`password`(str, AES-256-GCM 密文)、`totp`(str, 可选密文) | `{success, token, totp_required, username, is_default_password}` | 否 |
| GET | `/api/system/crypto-key` | 无 | `{key, name, version, totp_enabled}` | 否 |
| GET | `/api/system/info` | 无 | `{name, version, python_version, platform, uptime_seconds, plugin_count, server_time}` | 是 |
| GET | `/api/plugins/frontend-manifest` | 无 | `[{name, files:[...]}]`（插件前端脚本清单） | 否 |

**登录加密流（crypto-key + AES-256-GCM）**：
1. `GET /api/system/crypto-key` → 取 `key`（Base64 编码的 AES-256 密钥，每次进程启动随机生成于 `config/core.yaml` 的 `crypto.encryption_key`）。
2. 前端用该 key 对 `username` / `password` / `totp` 分别做 **AES-256-GCM** 加密：`CryptoUtils.encrypt` 产出 `Base64(nonce[12字节] + 密文+tag)`。
3. `POST /api/auth/login` 提交密文；服务端 `decrypt_field` 解密后 `authenticate` 校验（PBKDF2-SHA256 哈希比对），成功签发 JWT（HS256，默认有效期 1440 分钟，重启进程后旧 token 失效）。
4. `GET /api/system/info` 的 `version` 字段即程序内置**系统**版本号（当前 `20260805-V1`），用于登录后展示与冒烟校验；运维工具箱插件版本通过 `GET /api/opstoolbox/health` 的 `version` 字段查看（当前 `20260809-V7`）。

### 9.3 B 类客户端（`/api/opstoolbox/client/*`）

> 客户端**不走** `/tool/run`，而是各自独立的 `/client/*` 端点（Telnet 也是客户端，不是 `/tool/run` 工具）。下载类接口需先调 `/session/create` 取 `session_id`，文件落到该临时会话目录。

| POST | `/client/ftp/download` | `host`:str；`port`:int(21)；`username`:str("anonymous")；`password`:str；`tls`:bool；`remote_path`:str；`session_id`:str；`path_raw`:str（base64，**优先用于定位，修复中文名 550**） | `{success, message, data:{file, size}}` |

| POST | `/client/bulk/download` | `protocol`:str("ftp"/"sftp")；`host`:str；`port`:int(21/22)；`username`:str；`password`:str；`private_key`:str（sftp）；`tls`:bool(false)；`remote_dir`:str；`dir_raw`:str（可选）；`items`:list（每项 `{name, is_dir, raw, path_raw}`）；`session_id`:str | `{success, message, data:{file, size}}`；文件/文件夹递归打包为单个 **zip** 落到临时会话目录，经 `GET /session/download` 取回；**按 `path_raw` 逐字节定位，中文名/空格/多点扩展名混选不漏文件** |

> **上传链路**：前端先 `POST /session/upload`（`multipart/form-data`，字段 `file` + `session_id`）把本地文件落到临时会话目录，再 `POST /client/ftp|sftp/upload` 把该会话文件推到远端；`python-multipart` 为该链路必需依赖。WebDAV 客户端（`/client/webdav/*`）本轮已删除。

> 缺依赖时对应客户端返回友好提示而非 500：如 SSH/SFTP 缺 `paramiko` → `"缺少 paramiko 依赖"`；DNS 探测缺 `dnspython` → 在 `/tool/run` 链路返回 `"缺少 dnspython 依赖"`。

### 9.4 B 类服务端（`/api/opstoolbox/server/*`）

> 服务端句柄存于内存 `_SERVERS`（不持久化），统一经 `servers/__init__.py` 的 `ServerHandle`（`name/thread/stop_fn/port/started_at`）管理；`stop()` / `is_alive()` 暴露生命周期。

| Method | Path | 必填 / 可选参数（类型，缺省） | 返回形态 |
|---|------|-------------------------------|----------|
| POST | `/server/start` | `type`:str（ftp/sftp/webdav/tftp）；`host`:str("0.0.0.0")；`port`:int（ftp 2121 / sftp 2222 / webdav 8081 / tftp 69）；`username`:str("ops")；`password`:str（**留空=匿名/免密**）；`root`:str（必填，除非 `use_temp`）；`allow_write`:bool（仅 tftp） | `{success, server_id, port, root, type, temp_session}` |
| POST | `/server/stop` | `server_id`:str | `{success}` |
| GET | `/server/list` | 响应含 `local_ips`（本机全部 IPv4，20260806-V2 需求⑧） | 无 | `{servers:[{server_id, type, port, alive, started_at, root}]}` |
| GET | `/server/files` | `server_id`:str（query） | `{success, server_id, type, root, entries:[{name, is_dir, size, mtime}]}`（列出该服务端根目录下文件；FTP/SFTP/WebDAV 经协议列目录，TFTP 仅回显根目录文件元信息） |
| GET | `/server/connections` | `server_id`:str（query） | **需求⑧（20260806-V1 新增）** `{success, message, data:{active:[{peer,user,state,connected_at,duration,bytes_sent,bytes_recv,last_action}], history:[...], total:int, hint:str, supported:bool, server_id, type, port, root, started_at, alive}}`；`history` 含**登录失败**事件；`server_id` 不存在或已停止返回 `success:false`「服务端不存在或已停止」 |

启动规则（`routes/server.py:_start_server`）：`tftp` 默认端口 69、其余默认 2121（覆盖 `port` 参数）；密码留空时 FTP 走 `add_anonymous`、WebDAV 不启用认证、SFTP 允许空口令；若 `use_temp=true` 则自动创建临时会话目录作根（`root` 可省略），停止/卸载时随会话一并清理。根目录不存在或为空会返回对应错误提示。
