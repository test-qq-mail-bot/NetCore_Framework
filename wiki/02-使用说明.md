# 02-使用说明

本文档覆盖框架全部功能模块的操作说明，适用于日常使用。界面为单页应用（SPA），左侧菜单即功能入口。

---

## 1. 登录与登出

### 1.1 登录流程

1. 打开浏览器访问框架地址（如 `https://127.0.0.1:8080`），自动进入登录页。
2. 输入用户名和密码，点击「登录」。
3. 若启用了 TOTP 双因素认证，还需输入手机 App 生成的 6 位动态验证码。
4. 登录成功后自动跳转到仪表盘页面。

### 1.2 加密传输

前端对用户名、密码、TOTP 验证码统一做 **AES-256-GCM 加密**后提交，明文不过网：

1. 登录前自动调用 `GET /api/system/crypto-key` 获取一次性加密密钥
2. 前端用该密钥加密三个字段（username / password / totp）
3. 服务端解密后校验

> 你不需要手动实现加密逻辑，前端框架已封装在 `aesgcm.js` 中。

### 1.3 会话管理与心跳

- 登录成功后服务端创建会话登记（仅内存，重启后所有会话失效）
- 前端每 20 秒以上发一次心跳到 `/api/auth/heartbeat` 续期
- 空闲超过 `auto_logout_minutes`（默认 5 分钟，基础设置可改）自动退出
- 无操作超过阈值后，下一个请求会返回 401 强制跳回登录页

### 1.4 自动退出时间设置

在「基础设置 → 自动退出时间（分钟）」调整：

| 值 | 行为 |
| --- | --- |
| 0 | 关闭自动退出（会话永不超时，直到服务重启） |
| 1-1440 | 空闲超过该分钟数自动退出 |
| 默认 5 | 空闲 5 分钟自动退出 |

修改即时保存，无需重启。

### 1.5 登出

点击右上角用户名 → 「退出登录」。

## 3. 安全策略

安全策略页面管理三层防护：**失败策略**、**IP 白名单**、**IP 黑名单**。

### 3.1 失败策略

控制登录失败后的自动封禁行为：

| 字段 | 含义 | 默认值 | 范围 |
| --- | --- | --- | --- |
| 最大失败次数 | 同一 IP 在重置间隔内连续失败达到该值即自动拉黑 | 5 | 1-100 |
| 封禁时长(分钟) | 自动封禁的持续时间 | 10 | 1-1440 |
| 重置间隔(分钟) | 超过该间隔未再失败，计数清零重新累计 | 30 | 1-1440 |

点击「保存策略」即时生效，无需重启。

**自动封禁链路**：
1. 用户 IP 登录失败 → 计数 +1
2. 若 IP 在白名单中 → 跳过计数（免锁定）
3. 若超过重置间隔 → 计数清零重新累计
4. 计数 ≥ 最大失败次数 → 自动写入黑名单（`reason: "连续N次失败"`，`block_until = 当前时间 + 封禁时长`）
5. 计数清零
6. 黑名单条目到期后自动失效，恢复正常访问

### 3.2 IP 白名单

白名单是「受信任来源」列表，不是防火墙模式：

- **命中白名单的 IP 免除失败锁定计数**（即使登录失败也不会被拉黑）
- **不会阻止其他 IP 访问**（白名单不是"仅允许"模式）
- 适合放入管理员办公 IP、堡垒机 IP 等

**检查顺序**：白名单 → 黑名单 → 正常登录流程

#### 查看白名单

页面顶部表格展示全部条目：

| 列 | 说明 |
| --- | --- |
| IP / CIDR | 如 `192.168.1.100` 或 `10.0.0.0/8` |
| 说明 | 备注（如「管理员办公 IP」） |
| 有效期至 | 空 = 永久；有值 = 到期后自动失效 |
| 操作 | 「移除」按钮 |

#### 添加白名单

1. 顶部输入框填入 IP 或 CIDR
2. 填写说明（可选）
3. 选择有效期（可选，留空 = 永久）
4. 点击「添加」

同一 IP 不能同时存在于白名单和黑名单中，会返回 400 错误。

#### 移除白名单

点击条目右侧「移除」按钮，立即生效。

#### 回环地址特殊策略

`127.0.0.1` 与 `::1` 的行为：

- **仅在首次生成 security.yaml 时**自动写入白名单（备注「系统初始化-本地管理通道」）
- 之后框架**不再自动增删**这两个条目
- 如果你手工删除了回环白名单，重启后不会被加回
- 删除后意味着本机登录也受失败锁定约束，请谨慎

### 3.3 IP 黑名单

黑名单是「封禁来源」列表，命中且在封禁期内的 IP 访问返回 404（隐藏后台存在）。

#### 查看黑名单

| 列 | 说明 |
| --- | --- |
| IP / CIDR | 被封禁的地址 |
| 状态 | 「封禁中」（红色）/「已过期」（灰色）/「永久封禁」（红色） |
| 封禁/解封时间 | 空或「永久」= 永久封禁；有值 = 到期时间（按系统时区显示） |
| 说明 | 备注 |
| 操作 | 「移除」按钮 |

#### 封禁/解封时间列口径（重要）

| 条目状态 | 列显示 | 筛选下拉显示 |
| --- | --- | --- |
| 有效期为空（永久） | `永久` | `永久` |
| 有有效期/到期时间 | 到期日期时间（按系统时区换算） | 对应日期时间 |

> 封禁状态语义由「状态」列标签承担：封禁中 = 红色标签；已过期 = 灰色标签；永久封禁 = 红色标签。

#### 添加黑名单

1. 顶部输入框填入 IP 或 CIDR
2. 填写封禁分钟数（留空 = 永久）
3. 填写说明（可选）
4. 选择有效期至（可选，留空 = 永久）
5. 点击「添加」

**自动封禁条目**与手动添加的条目结构相同，区别在于自动条目含 `reason: "连续N次失败"` 和精确的 `block_until` 到期时间。

#### 移除黑名单

点击条目右侧「移除」按钮，立即生效。被封禁的 IP 立即恢复访问。

### 3.4 封禁期间的访问表现

被封禁的 IP 访问**任何接口**（包括首页、API、静态资源）都返回 404，不暴露后台存在。

## 4. 通知管理

支持四个通知渠道，用于安全告警、系统事件等场景。

### 4.1 渠道列表

| 渠道 | 说明 | 消息格式 |
| --- | --- | --- |
| email | SMTP 邮件 | HTML |
| wechat_work | 企业微信 Webhook | Markdown |
| dingtalk | 钉钉 Webhook（支持加签） | Text |
| feishu | 飞书 Webhook | Text |

### 4.2 查看渠道状态

「通知管理」页面展示各渠道的：
- 启用状态（开/关）
- 消息模板 ID
- 优先级

### 4.3 配置邮件渠道

| 字段 | 说明 | 默认 |
| --- | --- | --- |
| SMTP 服务器 | 如 `smtp.gmail.com` | - |
| 端口 | 默认 465（SSL） | 465 |
| SSL | 是否使用 SSL | true |
| 用户名 | SMTP 登录用户名 | - |
| 密码 | SMTP 登录密码（加密存储） | - |
| 发件人名称 | 显示名，如「NetCore 告警」 | NetCore Framework |
| 默认收件人 | 邮件地址列表 | [] |

### 4.4 配置 Webhook 渠道

| 字段 | 说明 |
| --- | --- |
| Webhook URL | 接口地址（加密存储） |
| 加签密钥（钉钉） | 签名密钥（加密存储），框架自动计算签名 |

### 4.5 频率限制

同一渠道最小发送间隔默认 60 秒，避免告警风暴。可在配置中调整。

### 4.6 发送测试

选中渠道 → 点击「测试」 → 即时发送测试消息。

成功与否都写入审计日志（action=`notify_test`），可在日志中心查看。

### 4.7 消息模板

使用 Go template 语法，模板上下文变量：

| 变量 | 说明 |
| --- | --- |
| `{{.Title}}` | 消息标题 |
| `{{.Content}}` | 消息正文 |
| `{{.Time}}` | 时间（已按系统时区格式化 `YYYY-MM-DD HH:MM:SS`） |

示例模板：
```yaml
templates:
  default:
    title: "[{{.Title}}] NetCore Framework 通知"
    body: |
      时间：{{.Time}}
      内容：{{.Content}}
```

## 5. 日志中心

### 5.1 运行时日志级别

调整全局日志级别（即时生效，重启保持）：

| 级别 | 输出内容 |
| --- | --- |
| DEBUG | 每个请求的明细日志（方法、路径、状态码、耗时） |
| INFO | 正常操作记录（默认） |
| WARNING | 异常但可恢复的情况 |
| ERROR | 错误与异常 |

在「日志中心」页面可热切换级别。

### 5.2 审计日志

全量记录关键操作：

| 操作类型 | action 标识 | 说明 |
| --- | --- | --- |
| 登录 | login_attempt | 成功/失败（含用户名不存在、密码错误、TOTP 校验失败） |
| 凭证回退 | login_plaintext_fallback | AES 解密失败回退明文 |
| 登出 | logout | 用户主动注销 |
| 安全策略变更 | security_policy_changed | 添加/删除白名单或黑名单、更新失败策略 |
| 基础设置变更 | basic_settings_updated | 保存基础设置（含变更前后对比） |
| 日志级别变更 | log_level_changed | 热切换日志级别 |
| HTTPS 证书上传 | https_cert_uploaded | 上传自定义证书/私钥 |
| HTTPS 开关 | https_switch | 启用或关闭 HTTPS |
| 会话重置 | session_reset | 重置当前会话 |
| 插件启用/禁用 | plugin_toggle | 启用或禁用单个插件 |
| 插件热重启 | plugin_reload | 热重启单个插件 |
| 插件全量重载 | plugin_reload_all | 热重启全部插件 |
| 插件重载失败 | plugin_reload_failed | 重载所有失败插件 |
| 通知配置变更 | notify_config_changed | 更新通知渠道配置 |
| 通知发送 | notify_send | 发送通知（含频率限制） |
| 通知测试 | notify_test | 测试通知渠道 |
| 审计日志清理 | audit_clean | 清空审计记录 |
| TOTP 绑定 | totp_bind | 绑定两步验证 |

#### 审计日志表字段

| 字段 | 说明 |
| --- | --- |
| 时间 | UTC 入库，展示按系统时区换算（`YYYY-MM-DD HH:MM:SS`） |
| IP | 客户端真实 IP（受信任反代的 X-Forwarded-For） |
| 用户名 | 操作用户 |
| 操作 | action 标识 |
| 结果 | success / failed |
| 详情 | 补充说明 |

#### 排序与筛选

- 点击列头切换升序/降序
- 每列支持筛选：点击筛选图标，输入值或选择下拉选项
- 时间列筛选下拉显示的是**换算后的时间**（与显示一致）

#### 导出

点击「导出CSV」下载审计记录：

- 首列为 `timestamp`（已按系统时区换算，格式 `YYYY-MM-DD HH:MM:SS`）
- 超过 20,000 条时发生截断，响应头 `X-Audit-Truncated: true`
- 截断时文件末尾追加说明行

也可选择 JSONL 格式导出。

#### 清理

点击「清理」清空全部审计记录（**不可恢复**，谨慎操作）。

### 5.3 审计日志文件

- 位置：`data/logs/audit/audit-YYYYMMDD.log`（按天 JSONL）
- 保留天数：`user_config.yaml → logging.audit_log_retention_days`（默认 60 天）
- 启动时自动清理超期文件（0 或负数 = 关闭自动清理）

### 5.4 运行日志文件

- 位置：`logs/YYYYMMDD-netcore.log`（按天 + 大小滚动）
- 单文件最大 10MB（`logging.max_bytes`）
- 保留 30 个轮转文件（`logging.backup_count`）

## 6. 插件管理

### 6.1 插件列表

「插件管理」页面展示每个插件：

| 字段 | 说明 |
| --- | --- |
| 名称 | 插件目录名 |
| 状态 | `success`（正常）/ `failed`（加载失败）/ `disabled`（已禁用） |
| 启用 | 开关（热重载即时生效） |
| 路由数 | 注册的 API 路由数量 |
| 版本 | 插件元信息中的版本号 |
| 描述 | 插件说明 |
| 路径 | 插件目录位置 |

### 6.2 启用/禁用

点击开关即时切换：

- **启用**：加载插件实例 → 补挂路由 → 菜单出现
- **禁用**：卸载插件实例 → 菜单消失 → 已挂路由保留到下次重启

> Starlette 不支持运行期摘除已 include 的路由，禁用后其 API 路由仍会保留到重启。这是架构限制，文档已明示。

### 6.3 热重启

| 按钮 | 行为 |
| --- | --- |
| 重启插件 | 热重启选中的单个插件 |
| 重启全部失败插件 | 仅重启 status=failed 的插件 |
| 重启全部 | 热重启所有已加载插件 |

热重启流程：优雅关闭旧实例（最长 5 秒） → 重新 importlib.reload 模块 → 重建实例 → 补挂路由。

### 6.4 新装插件

1. 把插件目录 `plugins/<name>/` 整体放入程序目录 `plugins/` 下
2. 重启框架
3. 框架自动发现并加载

**目录层级必须是** `plugins/<name>/plugin.py`，不要多套一层下载仓库文件夹。

示例：
```
plugins/
└── wiki_docs/          # ← 正确：直接放在 plugins 下
    ├── plugin.py
    ├── __init__.py
    └── frontend/
```

### 6.5 插件故障隔离

- 单个插件 import 或 `on_load()` 失败 → 标记为 `failed`，不影响其他插件与核心功能
- 修复后可单独重启该插件
- 失败插件的错误信息显示在插件管理页面

### 6.6 插件前端页面

- 页面脚本放 `plugins/<name>/frontend/*.js`（仅顶层目录）
- 脚本经 `/api/plugins/frontend-manifest` 列出、以 `/plugin-assets/<name>/` 注入
- **需要已登录会话**；未登录时打开页面，登录成功后会自动补拉脚本

## 7. 基础设置

### 7.1 系统设置

| 设置 | 说明 | 默认 |
| --- | --- | --- |
| 软件名称 | 自定义展示名，空则用内置值 | "" |
| 版本号 | 自定义版本号，空则用内置值 | "" |
| 时区 | IANA 名称（如 Asia/Shanghai），全站时间显示都按它换算 | Asia/Shanghai |
| 登录自动更新时区 | 开启后每次登录按浏览器时区覆盖上面的 timezone | true |
| 自动退出时间(分钟) | 无操作自动登出阈值；0=关闭 | 5 |
| 表单默认翻页数据 | 表格组件每页默认显示条数，可在输入框内填入 1~100 的任意数字 | 10 |

### 7.2 HTTPS 设置

| 设置 | 说明 |
| --- | --- |
| 上传证书 | 上传 `.crt/.pem` + `.key` 文件，PEM 文本落盘 |
| 启用 HTTPS | 总开关 |
| 自动跳转 | HTTP→HTTPS 反向协议跳转 |
| 跳转端口 | 跳转监听端口；空 = 主端口 +1 |
| SAN 域名 | 证书 SAN 显式地址列表（逗号分隔）；空 = 自动枚举 |

修改 HTTPS 设置后需重启完全生效。

### 7.3 修改即时生效

除 HTTPS 相关设置外，其他设置修改后即时保存生效，无需重启。

## 8. 使用文档菜单

即本套文档，内容来自程序目录 `wiki/` 的 Markdown 文件。

- 文件名去掉 `.md` 扩展名即菜单名
- 按文件名排序（00、01、02...）
- 把新的 `.md` 放入 `wiki/` 目录即可出现在菜单
- 无需重启，下次打开菜单时自动加载
