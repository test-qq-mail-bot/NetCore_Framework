# 数通配置卫士 (NetConfig Guardian) 插件开发项目书

> **版本**：20260805-V1  
> **依赖框架**：NetCore Framework 20260805-V1（程序内置版本号）  
> **插件标识**：`netconfig_guardian`  
> **设计理念**：基于 NetCore 微核心+插件化架构，构建轻量级、自动化的数通设备配置备份与变更审计系统。
>

---

## 一、插件概述

### 1.1 定位与目标

**数通配置卫士**是一款运行于 NetCore Framework 之上的业务插件，用于自动化采集多厂商数通设备的运行配置，检测配置变更，并通过框架内置通知渠道及时告警。插件提供完整的 Web 管理界面，支持设备管理、任务调度、变更历史查看及配置下载。

### 1.2 核心能力

- 支持 SSH/Telnet/SSH 密钥方式连接华为、华三(含海康OEM)、思科、锐捷、飞塔、TP-Link 的路由器、交换机、防火墙、AC 无线管理器。
- 内置多厂商驱动与样本库，可验证解析规则。
- 定时任务采用 Cron 表达式，灵活调度；支持手动触发、并发控制及超时管理。
- 基于文本 Diff 算法，与前一次采集配置进行对比，Web 端高亮展示差异，并提供基准配置下载。
- 利用框架通知模块，在配置变更或设备连接失败时通过邮件、企业微信、钉钉、飞书等渠道发送告警。
- 自身维护本地操作日志，并调用框架审计日志接口记录关键动作。

### 1.3 兼容性要求

- 运行于 NetCore Framework 所支持的 Python 3.10+ 环境，且框架已完成打包部署。
- 插件自身的 Python 依赖由 `requirements.txt` 声明，需包含 `netmiko`、`apscheduler`、`difflib`（标准库）等。

## 二、插件架构

### 2.1 整体分层

插件内部遵循 MVC 分层思想，与框架交互关系如下：

```

│  菜单: 仪表盘/设备管理/任务管理/通知中心/插件设置  │
│  （变更历史已合并到「设备管理」设备详情「设备配置」标签页内的「变更历史」区块，不再独立成页；新增「日志实时查询」标签页） │
└───────────────────┬──────────────────────────┘
                    │ HTTP API (JWT)
┌───────────────────▼──────────────────────────┐
│              插件 API 层 (FastAPI Router)      │
│  设备CRUD、任务管理、手动采集、Diff查询、日志    │
└───────────────────┬──────────────────────────┘
                    │
┌───────────────────▼──────────────────────────┐
│              插件业务逻辑层 (Service)          │
│  DeviceManager / TaskScheduler / BackupEngine │
│  DiffCalculator / NotifyHandler               │
└───────────────────┬──────────────────────────┘
                    │
┌───────────────────▼──────────────────────────┐
│              数据与基础设施层                   │
│  SQLite (guardian.db)                         │
│  文件存储: 配置采集原始文件、Diff结果、样本     │
│  框架集成: CryptoUtils, AuditLogger, NotifyAPI │
└──────────────────────────────────────────────┘
```

## 三、功能需求详述

### 3.1 设备管理

#### 3.1.1 设备模型

| 字段 | 说明 |
|------|------|
| id | 自增主键 |
| name | 设备名称 |
| ip | 管理IP |
| device_type | 设备类型 (router/switch/firewall/ac) |
| vendor | 厂商 (huawei/h3c/cisco/ruijie/fortinet/tplink) |
| auth_method | 认证方式 (password/ssh_key/telnet) |
| username | 登录用户名 |
| credential | 加密后的密码或SSH私钥短语 (AES-256-GCM) |
| ssh_key | 加密后的SSH私钥内容 (AES-256-GCM) |
| ssh_port | SSH端口 (默认22) |
| telnet_port | Telnet端口 (默认23) |
| enable_password | 加密后的 Enable/特权模式密码 (可选)。填写后会作为 netmiko 的 `secret` 传入，登录后自动 `enable` 进入特权模式；思科 IOS、锐捷等需要二次提权才能执行 `show running-config` 的设备**必须填写**，否则采集会因权限不足失败 |
| notify_recipients | 设备级通知接收人 (逗号分隔，可选) |
| health_status | 连接状态 (green=连通 / red=不连通) |
| last_backup_time | 最后成功采集时间 |
| last_fail_time | 最近失败时间 |
| consecutive_failures | 连续失败次数 |
| enabled | 是否启用采集 |
| auto_check_enabled | 是否启用自动检测可连接状态 (0/1) |
| auto_check_interval | 自动检测间隔（**秒**，v38 由分钟改秒；默认 300 秒，最小 5 秒；老库分钟值启动时一次性 ×60 迁移），插件启动后按此间隔轮询探测该设备连通性 |

#### 3.1.2 功能点

- **单独添加**：Web 表单填写设备信息，提供“测试连接”按钮，实时验证 SSH/Telnet 连通性及认证。
- **批量导入**：支持上传 CSV 文件或粘贴 CSV 内容，格式固定为：`name,ip,device_type,vendor,auth_method,username,credential,ssh_port,...`。导入时敏感字段直接加密存储。
- **编辑/删除**：编辑时可修改任何字段，删除时同时清理该设备所有备份及差异数据。
- **通知接收人**：可在编辑界面设置设备级通知接收人，不填则跟随全局配置。

### 3.2 任务管理与调度

#### 3.2.1 任务模型

| 字段 | 说明 |
|------|------|
| id | 自增主键 |
| name | 任务名称 |
| cron_expression | Cron 表达式 |
| device_ids | 选中的设备ID列表 (JSON数组，空或 `["__all__"]` 表示执行时**实时遍历全部设备**，后续新增设备自动纳入) |
| enabled | 是否启用 |
| last_run | 上次执行时间 |
| next_run | 下次预计执行时间 |

#### 3.2.2 功能点

- **任务 CRUD**：支持创建、编辑、启用/禁用、删除定时任务。
- **Cron 表达式**：提供下拉选项（每小时、每天2点、每周一3点、每月1号4点等）及自定义输入框，前端实时预览下次执行时间。
- **设备选择**：可为每个任务勾选设备，下拉框内置「全部设备(All)」与「清空选择」两个内置项（v41）；选「全部设备(All)」时存 `["__all__"]`，执行阶段实时遍历当前全部设备（新增设备自动纳入）。调度器执行时会对设备列表去重，同一采集轮次中一个设备只采集一次；**显式勾选的设备即使被禁用/已删除也会在任务日志中明确记录（不再静默丢弃）**（v41）。
- **手动触发**：提供“立即执行”按钮，可对选中的任务立刻运行一次，不受 Cron 限制。
- **调度引擎**：插件 `on_load()` 时使用 `apscheduler` 加载所有启用任务，动态管理。

### 3.3 配置采集与备份

#### 3.3.1 采集流程

1. 任务触发或手动调用 API。
2. 加载设备列表，通过并发控制 (Semaphore，默认20) 批量连接。
3. 根据设备厂商和类型加载对应驱动，发送采集命令（如 `display current-configuration`）。
4. 连接超时 (默认60秒) 或命令执行超时 (默认10分钟) 时标记失败。
5. 成功获取的原始配置以文本形式保存到 `data/backups/{device_id}/{yyyyMMdd-HHmmss}.cfg`。
6. 更新设备最后采集时间、健康状态及失败计数。

#### 3.3.2 厂商驱动与样本测试

- 插件内置 `drivers/` 目录，每个厂商一个模块，包含设备类型映射、采集命令、解析规则。
- 每个驱动目录下含一个 `samples/` 文件夹，存放真实回显样例。
- Web 界面“驱动管理”页面提供“测试解析”功能：选择厂商和类型，粘贴回显文本，调用后端解析接口返回是否成功提取配置段。

### 3.4 配置差异对比与下载

- **比较基准**：每次采集成功后，与该设备**前一次成功采集**的配置进行文本 Diff（使用 `difflib.unified_diff`）。
- **存储**：Diff 结果以 JSON 格式保存至 `data/diffs/{device_id}/{timestamp}.json`，包含增加行数、删除行数、完整 unified diff 文本。
- **Web 展示**：变更历史已合并到「设备管理」中每个设备的设备详情抽屉「设备配置」标签页内的「变更历史」区块（原独立「变更历史」页已取消），按时间倒序列出 Diff 记录，点击「查看」可展开完整 unified diff 文本（复用同一 `diffLines` 着色渲染）。
- **配置下载**：设备详情页提供“下载最新配置”按钮，返回最后一次采集的原始 `.cfg` 文件。

### 3.5 通知与告警

#### 3.5.1 触发条件

1. **配置变更**：Diff 发现差异后立即通知。
2. **设备健康状态变红**：连续采集失败达到 3 次时，状态置红，触发告警通知。

#### 3.5.2 通知配置

- 插件配置中可设置 `notify_on_change` (bool) 和 `notify_on_red` (bool) 独立开关。
- 全局接收人默认为 `notify.yaml` 中 `default_recipients` 的值，插件配置 `notify_recipients` 字段可逗号分隔追加。
- 设备级接收人覆盖全局设置。

#### 3.5.3 通知内容

使用框架 Go template 渲染，插件在 `notify.yaml` 中预设模板 `config_change` 和 `device_red`，示例变量：

```go
设备名称: {{.DeviceName}}
设备IP: {{.DeviceIP}}
变更时间: {{.ChangeTime}}
状态: {{.Status}}
```

### 3.6 插件本地日志

- 存储位置：`plugins/netconfig_guardian/logs/plugin.log`
- 记录内容：设备添加/删除、采集开始/结束/失败、配置变更发现、通知发送结果等。
- 格式：`[时间] [级别] [设备] 操作描述`
- Web 查看：独立页面“运行日志”，分页 20 行，支持按日期、级别筛选。
- 清理策略：默认保留 30 天，插件配置 `log_retention_days` 可调。

### 3.7 审计日志集成

插件通过 `core.audit.audit_log` 写入框架统一审计日志，记录粗粒度关键操作：

- `action="device_add"` / `device_delete`
- `action="backup_start"` / `backup_finish`
- `action="config_change_detected"`
- `action="notify_sent"`
- `username` 传入操作人（Web请求上下文）或 `"system"`。

### 3.8 插件设置

Web 界面“插件设置”子菜单可配置以下参数：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| task_execution_timeout | 600 (秒) | 单个设备采集任务总超时时间 |
| max_concurrent_devices | 20 | 一次性最大并发连接设备数 |
| device_connect_timeout | 60 (秒) | 单设备连接超时；已生效于 netmiko 真实连接（conn_timeout / banner_timeout / auth_timeout 均取此值，并设 fast_cli=False、global_cmd_verify=False，修复华为 VRP 报 "No existing session … conn_timeout 到 15 秒以上" 的问题） |
| log_retention_days | 30 | 本地日志保留天数 |
| notify_on_change | true | 配置变更时是否通知 |
| notify_on_red | true | 设备变红时是否通知 |
| consecutive_failures_for_red | 3 | 连续失败次数阈值 |
| notify_recipients | "" | 全局通知接收人 (逗号分隔) |
| topology_snmp_timeout | 5 (秒) | 拓扑发现单次 SNMP 查询超时（20260806-V1） |
| topology_max_depth | 3 | 拓扑递归发现最大深度；0=仅种子设备一层（20260806-V1） |

**保存行为**：点击「保存」会把设置写入 `plugins/netconfig_guardian/config/config.yaml`；目录不存在时自动创建。若因磁盘权限等原因写入失败，接口返回 **HTTP 500 并携带错误原因**，界面会明确提示保存失败——不会出现"提示成功但重启后设置丢失"的情况。因此看到保存成功提示即代表已真正落盘。

> 把 EXE 放在只读目录（如 `C:\Program Files`）会导致保存失败，请改放到有写入权限的目录。

### 3.9 网络拓扑（20260806-V1 新增）

利用设备管理已配置的 SNMP 信息（v2c/v3）获取设备接口的下游邻居生成拓扑，SNMP 查不了时降级 CLI（SSH/Telnet）命令回显解析。

**发现顺序**：读设备档案 `vendor` → 取该厂商 Profile → SNMP 查询（v2c/v3，LLDP-MIB 遍历）→ 失败转 CLI（LLDP/NDP 命令）→ 都失败标记原因不报错。

**厂商 Profile（按厂商差异化）**：

| vendor | 品牌 | SNMP 策略 | CLI LLDP 命令 |
|--------|------|-----------|---------------|
| huawei | 华为（含 eKitEngine） | LLDP 全量（含 ManAddr 表）+ NDP | `display lldp neighbor brief` |
| huawei_smart | 华为智选 FutureMatrix | LLDP 精简容错（ManAddr 缺失不致命）+ NDP | `display lldp neighbor brief`（复用华为解析） |
| h3c | 华三 | LLDP 全量 + NDP | `display lldp neighbor-information list` |
| cisco | 思科 | LLDP + CDP 双查 | `show lldp neighbors detail` / `show cdp neighbors detail` |
| ruijie | 锐捷 | LLDP 全量 | `show lldp neighbors` |
| fortinet / tplink | 飞塔 / TP-Link | LLDP 尽力而为 | 视型号（无则提示不支持） |

**核心机制**：
- **SNMP v3 引擎**（`snmp_v3.py`）：USM 发现流程（EngineID/Boots/Time）+ MD5/SHA 认证 + DES/AES-128 加密，复用已有 cryptography 库，零新增依赖。
- **品牌识别**：华为与智选**型号可能相同**（如 S5735S-L24T4X-QA2），区分靠 `disp ver` 首行品牌串（`Huawei` vs `FutureMatrix`）。采集设备信息时识别「实际品牌」（`device_info.brand`），与档案厂商不符时设备详情页提示；拓扑页支持按实际品牌重发现。
- **递归 BFS**：种子设备发现到「已知设备」邻居后自动向下一层扩展（visited 防环，深度上限 `topology_max_depth`）。
- **链路差异**：发现时对比旧快照，标注新增（绿）/消失（红）链路。
- **失败原因展示**：每台设备记录发现方式（snmp-lldp/snmp-cdp/cli-lldp/cli-ndp/none）与失败原因。
- **导出**：自包含 HTML（内嵌 SVG 拓扑图 + 节点/链路/发现明细表，离线可打开）；链路明细导出 Excel。

**三个入口**（共用同一发现引擎）：
1. 「网络拓扑」页交互发现（选种子设备，默认递归）；
2. 设备管理页多选设备 →「更新拓扑信息」批量按钮（`batch-action` action=topology，聚合执行不逐台）；
3. 定时任务类型「更新拓扑」（`task_type` 含 `topology`，任务级聚合执行一次并写入任务日志）。

### 4.1 表结构

```sql
CREATE TABLE devices (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    ip TEXT NOT NULL,
    device_type TEXT NOT NULL,
    vendor TEXT NOT NULL,
    auth_method TEXT NOT NULL,
    username TEXT NOT NULL,
    credential TEXT,
    ssh_key TEXT,

    telnet_port INTEGER DEFAULT 23,
    enable_password TEXT,
    notify_recipients TEXT,
    health_status TEXT DEFAULT 'green',
    last_backup_time TEXT,
    last_fail_time TEXT,
    consecutive_failures INTEGER DEFAULT 0,
    enabled INTEGER DEFAULT 1,
    auto_check_enabled INTEGER DEFAULT 0,

    updated_at TEXT DEFAULT (datetime('now'))
);

CREATE TABLE tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    cron_expression TEXT NOT NULL,
    device_ids TEXT,
    enabled INTEGER DEFAULT 1,
    last_run TEXT,
    next_run TEXT,
    created_at TEXT DEFAULT (datetime('now')),

    id INTEGER PRIMARY KEY AUTOINCREMENT,
    device_id INTEGER NOT NULL,
    file_path TEXT NOT NULL,

    FOREIGN KEY (device_id) REFERENCES devices(id)

    created_at TEXT DEFAULT (datetime('now')),

    node_count INTEGER DEFAULT 0,
    edge_count INTEGER DEFAULT 0,
    nodes_json TEXT,
    edges_json TEXT,
    status TEXT DEFAULT 'success',
    duration REAL DEFAULT 0,
    discover_scope TEXT
);
```

## 五、API 接口设计

所有接口均在插件路由 `/api/guardian/` 下，需携带有效 JWT。

### 5.1 设备管理

- `GET /api/guardian/devices` - 设备列表（分页、搜索）
- `POST /api/guardian/devices` - 添加设备
- `PUT /api/guardian/devices/{id}` - 编辑设备
- `DELETE /api/guardian/devices/{id}` - 删除设备
- 设备添加/编辑接口（`POST` / `PUT /api/guardian/devices`）额外接受 `auto_check_enabled`（0/1）与 `auto_check_interval`（**秒**，v38 由分钟改秒，默认 300，最小 5）；保存后插件按间隔自动轮询探测该设备连通性，失败计数复用"连续失败 N 次置红"机制（见 `consecutive_failures_for_red`），无需另设标红逻辑。
- `POST /api/guardian/devices/{id}/test` - 测试连接
- `POST /api/guardian/devices/batch-import` - 批量导入
- `GET /api/guardian/devices/{id}/latest-config` - 下载最新配置
- `POST /api/guardian/devices/batch-action` - 批量操作设备：`{action: "test"|"refresh_info"|"collect"|"delete", ids: [设备ID]}` → `{success, results:[{id,name,success,message,changed?}]}`（test=连通性测试 / refresh_info=从最近备份解析设备信息 / collect=采集备份 / delete=删除）

### 20260809-V5（本期）

- 版本号：数通配置卫士插件 `20260808-V4 → 20260809-V5`；框架未改动。
- ③ **「已选 x 台」移到设备列表标题右侧**：从批量操作按钮组内移出，放到「设备列表」标题右侧、搜索框左侧。
- ④ **SNMP v3 timed out 彻底解决（真实设备验证 PASS，六层根因）**：用 192.168.12.100 服务器对华为 S5735（10.10.201.13，User1/SHA-256/Cindy@921/AES-128/Cindy@221）逐层对比 net-snmp 成功报文修复：
  1. **msgGlobalData 未包 SEQUENCE**（RFC 3412 HeaderData 为 SEQUENCE）——旧报文把 msgID/maxSize/flags/secModel 扁平放，设备按标准解析直接丢弃；
  2. **msgMaxSize 必须 3 字节编码**（`02 03 00 FF E3`）——华为 VRP 对 msgGlobalData 字段按固定长度解析，2 字节最短编码错位；
  3. **engineTime 必须 4 字节编码**——time < 2^24 时最短编码 3 字节同样被 VRP 错位解析（此前一直报 usmStatsNotInTimeWindows 的根源）；
  4. **engineTime 需同步 discovery 后流逝秒数**（RFC 3414 时间窗）；
  5. **localized key 派生算法**：华为设备按 pysnmp/net-snmp 的 hash_passphrase 算法（密码环持续 hash 1M 字节 + 单次 H(master||engineID||master)）派生，旧实现按"1M 次迭代 H(Ku||eid||Ku)"密钥不一致 → usmStatsWrongDigests；已用 net-snmp 成功报文 authParams 逐字节验证 HMAC 匹配；
  6. **priv key 从 priv 密码独立派生 + AES 用 CFB-128 无 padding**（usmAesCfb128Protocol）：旧实现从 auth key 截断派生 + CBC+padding，设备解密失败 → usmStatsDecryptionErrors；另修复响应 scopedPDU 解析（先取 SEQUENCE value 再解析内部）。
  - **真实设备全链路 PASS**：discovery + GET(authPriv) 返回完整 sysDescr（S5735S-L24T4X-QA2，VRP 5.170），GETNEXT 返回 sysObjectID（1.3.6.1.4.1.2011.2.23.980 华为企业 OID）。
- ⑤ **v3 查询默认使用设备缓存配置**：打开设备详情时读设备 SNMP 配置填充 GET/GETNEXT 表单（不再写死 SHA-256/AES-128）；设备无配置时默认「无认证/无加密」。
- ⑥ **安全级别联动**：无认证无加密→noAuthNoPriv(flags=0x04)、仅认证→authNoPriv(0x05)、认证+加密→authPriv(0x07)；后端显式空串 auth 不再回退默认协议（前端 NONE sentinel 已衔接）。
- ⑦ **网络结论（修正）**：本机（192.168.12.101）与服务器（192.168.12.100）到 10.10.201.13/10.10.201.121 的 SNMP 与 SSH **均可达**（本机实测修复后客户端 discovery+GET 全链路 PASS，SSH 22 banner 正常）。此前本机 UDP 161 超时并非 ACL 拦截，而是**客户端报文不合规（msgGlobalData SEQUENCE 缺失等）被设备丢弃**——报文修复后本机直接可用。
- ⑧ **拓扑发现（修正）**：报错 `No module named 'plugins.netconfig_guardian.engine.snmp'` 在最新源码不存在（源码为 engine/topology/snmp.py），确认为**旧版本程序**导致（本机/服务器 SSH 均可达，非 ACL）；CLI 认证失败 `transport shut down or saw EOF` 同源于旧版本。请用最新 exe 测试——SSH 连接链路未改动（与设备列表「测试连接」共用同一连接参数）。
