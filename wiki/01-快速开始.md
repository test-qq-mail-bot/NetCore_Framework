# 01-快速开始

本文档覆盖从零到成功登录的完整过程，包括 EXE 单文件部署与源码开发两种方式。

---

## 1. 环境要求

| 部署方式 | 要求 |
| --- | --- |
| EXE 单文件（推荐） | Windows 10/11 或主流 Linux 发行版；无需安装 Python |
| 源码运行（开发模式） | Python 3.13；pip / uv 包管理器 |

浏览器要求：Chrome / Edge / Firefox 现代版本（支持 ES2020+）。

---

## 2. EXE 单文件部署（推荐）

### 2.1 获取程序

从发布页下载 `netcore-framework.exe`（Windows）或 `netcore-framework`（Linux），放到一个**有写权限的独立目录**。

建议目录结构：

```
NetCore-Dist/               # 你选择的部署目录
└── netcore-framework.exe   # 放入此处
```

> **重要**：程序首次运行会在**同目录**自动生成以下子目录，不要提前手动创建：
> - `config/` — 四份配置文件（core.yaml / user_config.yaml / security.yaml / notify.yaml）
> - `data/` — 数据库、证书、审计日志
> - `logs/` — 运行日志（按天滚动）
> - `plugins/` — 业务插件目录
> - `frontend/` — 前端静态资源
> - `wiki/` — 内置文档集

### 2.2 首次启动

双击运行（或命令行 `./netcore-framework.exe`）。

控制台输出示例：

```
INFO:     NetCore Framework 20260826-V6 启动中...
INFO:     HTTPS 已启用（自签名证书）
INFO:     实际监听地址：https://0.0.0.0:8080
INFO:     反向协议跳转：http://0.0.0.0:8081 → https://0.0.0.0:8080
INFO:     插件已加载：成功 N / 失败 0 / 禁用 0
```

**以控制台打印的实际地址为准**（端口可能因冲突自动顺延）。

首次启动自动完成：
1. 生成四份配置文件（含默认密码、JWT 密钥、回环白名单等）；
2. 生成自签名 HTTPS 证书到 `data/certs/`；
3. 白名单写入 `127.0.0.1` 与 `::1`（备注「系统初始化-本地管理通道」）；
4. 启动反向协议跳转监听（主端口 +1，HTTP 访问自动跳 HTTPS）。

### 2.3 验证安装

打开浏览器访问控制台打印的地址（如 `https://127.0.0.1:8080`），看到登录页即成功。

### 2.4 默认账号

| 项 | 值 |
| --- | --- |
| 用户名 | `admin` |
| 密码 | `Admin@123!` |

> 首次登录后请立即修改密码。修改方式见第 5 节。

## 3. 源码运行（开发模式）

### 3.1 获取源码

```bash
git clone <仓库地址> NetCore-Framework
cd NetCore-Framework
```

### 3.2 创建虚拟环境（推荐 uv）

```bash
# 推荐 uv（速度快、依赖解析可靠）
uv venv --python 3.13 .venv

# 激活环境
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Windows CMD:
.venv\Scripts\activate.bat
# Linux / macOS:
source .venv/bin/activate
```

### 3.3 安装依赖

```bash
# 运行时依赖 + 构建期依赖（含 pytest、ruff）
uv pip install -r requirements.txt -r requirements-dev.txt --python .venv

# 或传统 pip：
pip install -r requirements.txt -r requirements-dev.txt
```

### 3.4 运行

```bash
python main.py
```

### 3.5 运行测试

```bash
# uv 环境
.venv\Scripts\python.exe -m pytest tests -q

# 或激活环境后
pytest tests -q
```

预期输出：`7 passed in X.Xs`

## 4. HTTPS 说明

### 4.1 默认行为（自签名）

框架默认启用 HTTPS 并生成自签名证书，浏览器会提示「不安全」或「您的连接不是私密连接」。

这是**正常现象**——自签名证书不被浏览器信任，但通信仍然加密。

绕过方式：
- Chrome/Edge：点击「高级」→「继续前往...（不安全）」
- Firefox：点击「高级」→「接受风险并继续」

### 4.2 上传正式证书

消除浏览器告警：「基础设置 - HTTPS」上传受信任证书。

| 文件 | 说明 |
| --- | --- |
| 证书文件（`.crt` / `.pem`） | PEM 格式，包含完整证书链 |
| 私钥文件（`.key`） | PEM 格式私钥 |

上传后证书以 PEM 文本落盘到 `user_config.yaml` 的 `https.cert_content` / `https.key_content`，重启后生效。

也可手工编辑 `config/user_config.yaml` 直接粘贴 PEM 内容。

### 4.3 证书 SAN 校验

远程客户端访问时，浏览器会校验证书的 Subject Alternative Names（SAN）。

自签名证书自动枚举以下地址作为 SAN：
- 本机所有非回环网卡 IP（如 `192.168.1.100`）
- `localhost`、`127.0.0.1`

如果远程通过其他 IP/域名访问且报 SAN 不匹配：
1. 在 `user_config.yaml → https.domain` 填写访问地址（逗号分隔多个）
2. 重启程序，自签名证书会包含这些地址

示例：
```yaml
https:
  domain: "192.168.1.100,myserver.local"
```

### 4.4 关闭 HTTPS

如果你有反向代理（Nginx/Caddy）在前端做 TLS，可以关闭框架的 HTTPS：

```yaml
# config/user_config.yaml
https:
  enabled: false
  auto_redirect: false      # 同时关闭跳转监听
```

重启后框架以纯 HTTP 运行。**建议同时清空 `redirect_port` 避免无用监听**。

## 5. 修改密码

框架暂不支持界面修改密码，通过编辑配置文件完成：

### 步骤

1. 编辑 `config/user_config.yaml`
2. 在 `auth:` 段手动添加一行：

```yaml
auth:
  username: admin
  password_hash: "..."    # 保持不动，框架自动处理
  password_plain: "MyNewPassword123!"   # ← 新增这行
```

3. 保存文件，重启程序
4. 框架检测到 `password_plain`：
   - 用明文密码生成新哈希写入 `password_hash`
   - **删除** `password_plain` 行
   - 输出日志：`已重置管理员密码，请使用新密码登录`
   - 程序退出
5. 再次启动程序，用新密码登录

> **安全提示**：`password_plain` 是一次性字段，框架处理后立即删除。如果程序没有自动退出，说明密码重置流程未触发，请检查字段位置是否正确。

## 6. 启用 TOTP 双因素认证

TOTP（基于时间的一次性密码）为可选的第二层认证，需配合手机 App（如 Google Authenticator、Microsoft Authenticator）使用。

### 开启方式

1. 登录后进入「安全策略」页面
2. 点击「开启 TOTP」按钮
3. 用手机 App 扫描二维码（或手动输入密钥）
4. 输入 App 生成的 6 位验证码完成绑定

### 关闭方式

编辑 `config/user_config.yaml`：

```yaml
auth:
  totp_enabled: false
  totp_secret: ""
```

重启后 TOTP 关闭，登录时不再要求验证码。

## 7. 端口与网络

### 7.1 默认端口

- 主服务：`8080`（HTTPS 模式对外）
- 跳转服务：`8081`（HTTP→HTTPS 自动跳转，主端口 +1）

### 7.2 端口冲突处理

如果配置端口被其他程序占用，框架自动顺延 +1 ~ +20 尝试，直到找到可用端口。

**以控制台打印的实际地址为准。**

固定端口建议在 `config/core.yaml` 显式指定：

```yaml
server:
  port: 9000    # 改为你需要的端口
```

### 7.3 防火墙放行

远程访问需放行防火墙入站规则：
- 主端口（如 8080）
- 跳转端口（如 8081，如已启用 auto_redirect）

## 8. 首次登录后验证清单

登录成功后，逐项确认：

| 检查项 | 位置 | 预期 |
| --- | --- | --- |
| 默认密码已修改 | 修改密码流程（第 5 节） | 用新密码登录成功 |
| 失败策略已确认 | 安全策略 → 失败策略 | max_failures=5, block_minutes=10 |
| 时区正确 | 基础设置 → 时区 | 显示的服务器时间与本地一致 |
| HTTPS 正常 | 浏览器地址栏 | HTTPS 锁图标（自签名会告警，属正常） |
| 审计日志有记录 | 日志中心 → 审计日志 | 刚才的登录记录可见 |
| 插件状态正常 | 插件管理 | 所有插件 status=success |
