## 2. 分层架构

```
浏览器 SPA（Vue 3 + Element Plus 离线全局构建，运行时编译模板）
        │  /api/*（Bearer JWT）      │  /assets、/plugin-assets（静态）
FastAPI 应用层
 ├─ core/framework.py     装配：中间件链、路由注册、静态挂载、SPA 兜底、资源提取
 ├─ core/api.py           六组 REST 路由（auth/security/notify/audit/system/plugins）
 ├─ core/auth.py          登录、JWT 签发/校验、TOTP、字段解密、认证依赖
 ├─ core/security.py      IP 黑白名单匹配、失败锁定与自动封禁链路
 ├─ core/session.py       会话管理（内存表、心跳续期、空闲超时）
 ├─ core/audit.py         审计日志（JSONL 按天文件、查询/导出/清理、线程安全写入）
 ├─ core/notify.py        四渠道通知 + Go template 渲染 + 频率限制
 ├─ core/plugin_manager.py插件发现/加载/热重载/菜单聚合/路由挂载
 ├─ core/config_loader.py 四配置文件的引导、迁移、原子写入、缓存、并发保护
 ├─ core/timeutil.py      统一时间基准（UTC 入库 / 配置时区显示）
 ├─ core/crypto_utils.py  AES-256-GCM 加解密 + PBKDF2 密码哈希
 ├─ core/logger.py        按天滚动日志 + 动态级别调整 + uvicorn 绑定
 ├─ core/https_utils.py   自签名证书生成/校验、NIC IP 枚举、HTTPS 配置
 ├─ core/gotemplate.py    Go template 渲染引擎
 └─ plugins/<name>        业务插件（BasePlugin 子类，路由 + 菜单 + frontend）
存储层：SQLite（插件业务库）+ YAML 配置 + 按天滚动日志文件
```

## 3. 启动流程

### 3.1 模块导入期（EXE 模式）

PyInstaller onefe 模式下，内嵌资源在 `_MEIPASS` 临时目录。启动时：

1. **合并提取**：将 `_MEIPASS` 内的 `frontend/`、`wiki/`、`plugins/` **递归合并**到程序目录
   - 跳过 `data/`、`logs/`、`__pycache__`（用户数据不覆盖不删除）
   - 新增的前端文件会被拷贝，已有文件按修改时间决定是否覆盖
2. **清理孤儿前端 JS**：对打包内自带插件（非外部部署的），删除 `plugin.py` 已不存在的前端 JS（避免升级后残留）
3. **挂载外部插件目录**：将程序目录 `plugins/` 挂入 `plugins` 包的模块搜索路径（使 `importlib.import_module("plugins.xxx.plugin")` 能找到外部插件）

### 3.2 create_app()

1. 注册中间件链（从外到内）：
   - 安全响应头（X-Content-Type-Options / X-Frame-Options:DENY / Referrer-Policy）
   - 工具箱禁缓存（对 `/api/opstoolbox`、`/plugin-assets/ops_toolbox` 追加 no-store）
   - IP 黑白名单检查（`check_ip`：白名单放行 → 黑名单 404 → 放行）
   - 审计 IP 注入（X-Forwarded-For 仅受信任反代）
   - 访问日志（DEBUG 级输出方法/路径/状态码/耗时）
2. 六组 API 路由挂载（auth/security/notify/audit/system/plugins）
3. 静态资源挂载：`/assets` → `frontend/`，逐插件 `/plugin-assets/<name>` → `plugins/<name>/frontend/`
4. favicon 路由：`/favicon.svg`、`/favicon.ico`
5. 404 兜底：含扩展名 → JSON 404；其余回退 `index.html`

### 3.3 lifespan 启动

1. **bootstrap**（config_loader）：
   - 创建必要目录
   - 写入默认配置文件（首次）
   - 密码兜底修复（password_hash 损坏时用默认密码重建）
   - 插件名扫描（refresh_detected_plugins）
   - 旧段迁移（core.yaml 中遗留的 logging/notify/session/https/debug 段迁移到 user_config.yaml）
   - 注释重渲染（保留中文注释）
2. **通知配置重载**
3. **日志初始化**（setup_logger）
4. **password_plain 检查**：存在则重置密码并退出
5. **审计保留期清理**（cleanup_audit_by_retention）
6. **插件加载**（load_all + mount_routes）
7. 打印启动完成信息

### 3.4 Uvicorn 监听

- 主端口：配置端口（默认 8080），被占用自动顺延 +1~+20
- HTTPS 模式额外启动 `redirect_port` 的反向协议跳转服务（HTTP→HTTPS 自动跳转）

## 4. 时间基准

### 4.1 规范

**所有落库的时间戳一律以 UTC 存储**（与 SQLite 的 `datetime('now')` 保持一致），前端统一通过 `NC.fmtTime()` 按用户配置时区换算显示。

### 4.2 入库层

使用 `core/timeutil.py` 的 UTC 函数：

| 函数 | 格式 | 用途 |
| --- | --- | --- |
| `utc_now()` | datetime（naive） | datetime 字段 |
| `utc_now_iso()` | `2026-08-26T15:36:57.123456` | ISO 字段 |
| `utc_now_str()` | `2026-08-26 15:36:57` | 与 SQLite datetime('now') 同格式 |
| `to_utc_str(dt)` | `2026-08-26 15:36:57` | 本地时间转 UTC（带时区自动换算） |

### 4.3 展示层

- 前端：`NC.fmtTime(v)` 按 `user_config.yaml → system.timezone` 用 `Intl.DateTimeFormat` 换算
- 服务端导出：`timeutil.fmt_utc(ts)` 在服务端完成同样换算
- 格式：`YYYY-MM-DD HH:MM:SS`，不含时区后缀与毫秒

### 4.4 Windows 时区库

Windows 下 `zoneinfo` 模块需要 `tzdata` 包提供 IANA 时区数据。`requirements.txt` 已锁定 `tzdata==2026.3`，打包版自带。

## 5. 安全链路

### 5.1 请求处理链

```
请求 → security_middleware
        ├─ 记录客户端真实 IP（trusted_proxies 内才信任 X-Forwarded-For）
        ├─ check_ip：
        │   ├─ 白名单命中 → 放行（免失败锁定计数）
        │   ├─ 黑名单命中且在封禁期 → 404（隐藏存在）
        │   └─ 放行
        └─ 路由处理器
```

### 5.2 登录认证链

```
前端：username + password + totp → AES-256-GCM 加密 → POST /api/auth/login
        │
服务端：decrypt_field（传输密钥 → 主密钥 → 明文回退）→ authenticate
        ├─ 用户名校验
        ├─ 密码校验（PBKDF2-SHA256，恒定时间比较）
        ├─ TOTP 校验（如启用，pyotp，valid_window=1）
        │
成功 → create_token（JWT HS256）→ 记录 last_login → 审计日志
失败 → 计数 +1 → 检查阈值 → 自动封禁（如达到）
```

### 5.3 失败锁定链路

```
登录失败 → record_failure(ip)
        白名单豁免 → 重置间隔外清零计数 → count ≥ max_failures
        → _add_blacklist(block_until=now+block_minutes, reason="连续N次失败")
        → 计数清零
登录成功 → reset_failures(ip)
```

### 5.4 密钥层次

| 密钥 | 用途 | 位置 |
| --- | --- | --- |
| AES 主密钥 | 加密落盘敏感数据（TOTP secret、通知密码、Webhook URL） | core.yaml → crypto.encryption_key |
| 传输派生密钥 | 前端登录加密（HMAC-SHA256 派生，不暴露主密钥） | /api/system/crypto-key 下发 |
| JWT 签名密钥 | HS256 签发/校验 Token | core.yaml → jwt.secret_key |
| PBKDF2 盐 | 密码哈希 | 每次哈希随机生成，内嵌在哈希串中 |

## 6. 中间件与 404 兜底

| 层 | 行为 |
| --- | --- |
| 安全响应头 | X-Content-Type-Options:nosniff / X-Frame-Options:DENY / Referrer-Policy:no-referrer |
| 工具箱禁缓存 | 对 `/api/opstoolbox`、`/plugin-assets/ops_toolbox` 追加 Cache-Control: no-store |
| IP 名单 | 黑名单命中返回 404（隐藏后台存在） |
| 访问日志 | DEBUG 级输出方法/路径/状态码/耗时 |
| 404 兜底 | 含扩展名路径 → JSON 404；API/assets/docs 前缀 → JSON 404；其余回退 index.html 由前端路由接管 |

## 7. 插件生命周期

详见《05-插件开发指南》第 3 节。核心原则：

- **故障隔离**：单插件 import/on_load 失败仅标记 failed，不影响其他插件与核心功能
- **幂等加载**：load_all 先卸旧再装新，避免重复实例与双倍后台线程
- **路由语义**：运行期启停只影响生命周期，已挂路由保留到重启；启用后由 mount_new_routes 补挂
- **外部插件目录**：将程序目录 `plugins/` 挂入 `plugins` 包的模块搜索路径，使 EXE 打包之外的外部插件也能被 importlib 找到

## 8. 前端机制

### 8.1 SPA 架构

- 单页应用：`index.html` + 离线 Vue3/ElementPlus
- 页面组件通过 `NC.registerPage(id, component, title)` 注册到 `NC.PAGES`
- 核心页随包静态加载；插件页脚本登录后按清单动态注入并统一注册

### 8.2 路由约定

- 格式：`/<plugin>/<page>` → 组件 id `<plugin>_page`
- 特殊映射走 `NC.PATH_MAP`（仅约定推导失败时使用）
- 组件 id 必须与菜单 `id` 一致

### 8.3 全局能力

- `NC.http`：axios 实例，Bearer 自动注入，401 统一处理回登录视图
- `NC.fmtTime`：UTC → 系统时区格式化
- `NC.NcTable`：声明式表格（排序/筛选/分页）
- `NC.SF_MIXIN`：前端数组表排序/筛选 mixin
- `NC_aesEncrypt`：AES-256-GCM 加密（与后端兼容）
- SVG 图标表（dashboard/setting/security/bell/log/plugin/guardian/doc/chevron）

### 8.4 版本管理

- 前端静态资源通过 `?v=` 缓存参数防缓存（index.html 的 `nc-asset-version`）
- 插件 JS 由 manifest 按 mtime 自动失效缓存
- `NC.verLT(a, b)` 比较 `YYYYMMDD-Vn` 格式版本号，自动检测过期缓存并提示刷新
