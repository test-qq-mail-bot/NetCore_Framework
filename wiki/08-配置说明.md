# 03 - 配置说明

框架的运行时配置全部位于可执行文件**同级目录**的 `config/` 下，共四份文件。
配置文件均带**中文行内注释**，改动后多数即时生效（标注「需重启」的除外）。

| 文件 | 权限 | 用途 | 生效方式 |
|------|------|------|----------|
| `core.yaml` | **只读** | 服务端口、JWT、日志、会话、加密密钥、通知频率限制 | 修改需重启 |
| `user_config.yaml` | 可读写 | 密码哈希、TOTP、插件关闭列表、系统名称/版本 | 部分即时生效 |
| `security.yaml` | 可读写 | IP 黑白名单、登录失败策略 | 即时生效 |
| `notify.yaml` | 可读写 | 邮件/企业微信/钉钉/飞书渠道与消息模板（敏感字段加密存储） | 即时生效 |

> 若文件不存在，框架启动时会**自动生成默认配置**，无需手工创建。

---

## 1. core.yaml（核心配置，只读）

> 此文件由框架自动维护，通常**不要手工修改**；修改后必须重启服务。

```yaml
server:
  host: "0.0.0.0"          # 监听地址，0.0.0.0 表示监听所有网卡
  port: 8080               # 监听端口号（被占用时自动顺延，见下文）
  debug: false             # 调试模式，生产环境必须 false

crypto:
  encryption_key: ""       # AES-256-GCM 加密密钥（Base64），首次启动自动生成

jwt:
  secret_key: ""           # JWT 签名密钥，每次启动自动重新生成（旧 Token 失效）
  expire_minutes: 1440     # Token 有效期（分钟），默认 24 小时

logging:
  level: "INFO"            # 日志级别：DEBUG / INFO / WARNING / ERROR
  file: "data/logs/"       # 日志目录（仅作路径说明），实际按天写入 {日期}-netcore.log
  max_bytes: 10485760      # 单文件最大字节数（10MB）
  backup_count: 30         # 保留日志文件个数
  audit_log_retention_days: 60   # 审计日志保留天数，过期自动清理

notify:
  rate_limit:
    enabled: true           # 是否启用通知频率限制
    min_interval_seconds: 60  # 同一渠道两次发送最小间隔（秒）
```

### 端口冲突自动顺延

默认端口 `8080` 被占用时，框架会在**控制台**打印提示，并临时加端口号直到不冲突（如 8081、8082…），然后正常启动。访问地址以控制台提示为准。该行为无需修改配置。

## 2. user_config.yaml（用户配置，可读写）

> 由框架自动维护；手工修改请遵循格式。启用/禁用插件请在 Web 后台「系统管理-插件列表」操作（或调 `POST /api/plugins/{name}/toggle`），修改后自动重新加载插件，无需手工重启。

```yaml
system:
  name: ""                # 自定义软件名称（空则使用内置默认值）
  version: ""             # 自定义版本号（空则使用内置默认值）
  auto_logout_minutes: 5  # 自动退出时间（分钟）：无操作超过该时长自动退出；0=关闭

auth:
  username: "admin"       # 管理员用户名（固定为 admin，暂不支持多用户）
  password_hash: "pbkdf2_sha256$600000$..."  # 密码哈希（PBKDF2-SHA256，迭代 600000）
  totp_enabled: false     # TOTP 双因素认证开关
  totp_secret: ""         # TOTP 密钥（Base32，绑定时自动写入）

plugins:
  detected: ["netconfig_guardian", "wiki_docs"]   # 每次启动自动重新扫描 plugins/ 并写入「所有检测到的插件」（仅作记录，不参与启停判定）
  disabled: []                                      # 关闭列表：为空表示启用全部已发现插件（wiki 插件默认启用）；将插件名加入此列表即可停用该插件
```

> 说明：启用/禁用插件改在 Web 后台「系统管理-插件列表」操作；`detected` 由框架维护**无需手改**；要停用某插件就把它加入 `disabled`。旧版本的 `plugins.enabled` 白名单字段已废弃，请勿再使用。

### 自动退出（空闲超时）

基础设置中的「自动退出时间（分钟）」对应 `system.auto_logout_minutes`：

- 默认 `5` 分钟；设为 `0` 表示**关闭自动退出**（token 仅受 JWT 绝对有效期约束）。
- 有效操作（点击、在输入框内键盘输入、切换页面）会刷新计时器；鼠标移动与页面滚动**不计入**。
- 超过设定时长无任何有效操作，前端自动清除登录态并退回登录页；同时后端按相同阈值做空闲校验——即使前端被破坏或不发送心跳，token 也会在服务端到期失效（返回 401），形成双重保险。
- 后端阈值实时读取本配置，保存后立即对新会话生效。

### 如何重置管理员密码

框架内置支持密码重置机制（由 `_check_password_reset` 实现），**无需在配置文件里新增任何常驻字段**——仅在需要重置时临时加一行明文密码，重启后框架会自动加密并清空。步骤如下：

1. **停止程序**（关闭正在运行的 NetCore Framework 进程）。
2. 用记事本（或任意文本编辑器）打开 `config/user_config.yaml`，在 `auth:` 下**临时添加一行** `password_plain: "你想设置的新明文密码"`，注意引号与缩进，与 `password_hash` 同级，例如：

   ```yaml
   auth:
     username: "admin"
     password_hash: "pbkdf2_sha256$600000$..."
     password_plain: "你想设置的新明文密码"   # ← 仅临时重置用，重置成功后程序会自动清空
     totp_enabled: false
     totp_secret: ""
   ```
3. **启动程序一次**：框架检测到 `password_plain` 后会自动把明文用 PBKDF2-SHA256 加密写入 `password_hash`、清空 `password_plain` 字段、并重置 TOTP 双因素，然后**自动退出**。
4. **再次正常启动程序**，即可用新密码登录，旧密码随之失效。

> **要点**：
> - `password_plain` 仅作**一次性重置**用途；重置成功后程序会自动清空该字段，**无需手工删除**。
> - 留空或不填 `password_plain` 不影响程序正常运行。
> - 重置密码会一并重置 TOTP：`auth.totp_enabled` 会被置为 `false`、`auth.totp_secret` 会被清空，避免旧 TOTP 密钥/开关残留导致无法登录；若此前已开启 TOTP，改密后需重新绑定。
> - 该机制由框架内置支持，**无需额外配置字段**，也不在配置文件中持久保存明文密码。

## 3. security.yaml（安全策略，可读写，即时生效）

```yaml
failure_policy:
  max_failures: 5         # 连续失败次数阈值
  block_minutes: 10       # 达到阈值后封禁分钟数
  reset_interval_minutes: 30  # 计数重置间隔

whitelist: []              # 白名单（IP 或 CIDR），非空时仅放行列表内地址
  # - "192.168.1.100"
  # - "10.0.0.0/8"

blacklist: []              # 黑名单（永久或限时封禁）
  # - ip: "203.0.113.45"
  #   block_until: "2026-07-07T10:30:00Z"
  #   reason: "连续5次失败"
  #   fail_count: 5
```

检查顺序：**白名单 → 黑名单 → 正常登录**。
回环地址（`127.0.0.1`/`::1`）仅在**首次生成 security.yaml 时**自动写入白名单（备注"系统初始化-本地管理通道"）；此后框架不再自动增删，可按需手工移除。

> **V5 提示**：Web 后台「系统管理 - 安全策略」的 IP 名单表格，「封禁/解封时间」列统一只显示**「永久」或按系统时区换算后的具体时间**（数据来自条目的 `block_until`/`expires_at` 字段）；封禁状态语义由「状态」列标签承担（封禁中 / 已过期 / 永久封禁 / 有效）。时间筛选下拉中无时间的条目显示为"(空)"。

## 4. notify.yaml（通知配置，可读写，敏感字段加密）

> 密码、Webhook URL、加签密钥等敏感字段以 AES-256-GCM 加密存储；保存时若某敏感字段为空，视为「不更新」，保留原值。

```yaml
templates:
  default: |               # 全局默认模板（Go template 语法）
    {{if eq .Priority "high"}}[紧急] {{end}}{{.Title}}
    时间：{{.Time}}  来源：{{.Source}}
    {{.Content}}
  alert: |
    **告警通知**
    > 优先级：{{.Priority}}  时间：{{.Time}}  来源：{{.Source}}
    {{.Content}}
  info: |
    信息通知：{{.Title}}
    {{.Content}}

email:                    # 邮件渠道
  enabled: false
  smtp_host: ""
  smtp_port: 465
  smtp_ssl: true
  username: ""
  password: ""            # 加密存储
  sender_name: "NetCore Framework"
  default_recipients: []
  cc: []; bcc: []
  priority: "normal"
  template: "default"

wechat_work:              # 企业微信
  enabled: false
  webhook_url: ""         # 加密存储
  priority: "normal"
  template: "default"

dingtalk:                 # 钉钉
  enabled: false
  webhook_url: ""         # 加密存储
  secret: ""             # 加签密钥，加密存储
  priority: "normal"
  template: "default"

feishu:                   # 飞书
  enabled: false
  webhook_url: ""         # 加密存储
  secret: ""             # 签名校验密钥，加密存储
  priority: "normal"
  template: "default"
```

### 消息模板可用变量

| 变量 | 说明 |
|------|------|
| `{{.Title}}` | 通知标题 |
| `{{.Content}}` | 通知正文 |
| `{{.Priority}}` | 优先级：high / normal / low |
| `{{.Channel}}` | 发送渠道 |
| `{{.Time}}` | 通知时间（ISO 8601） |
| `{{.Source}}` | 来源（插件名或 "system"） |
| `{{.Extra}}` | 调用方传入的额外键值对 |

## 5. 配置与目录权限

- 程序首次运行会创建 `config/`、`data/logs/`、`plugins/`、`frontend/`、`wiki/`。
- 若运行目录**无写入权限**，程序直接报错退出（不回退到其他目录），以保证运行环境一致。
- 升级时建议备份 `config/`、`data/`、`plugins/` 后再替换可执行文件。
