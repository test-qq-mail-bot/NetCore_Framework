## 一、项目概述

### 1.1 项目定位

开发一个**轻量级、插件化的通用后端底层框架**，为后续业务模块提供稳定、可扩展的运行基础。框架本身**不包含任何业务功能**，所有能力均以独立插件形式接入。

### 1.2 核心设计目标

| 目标 | 详细说明 |
|------|----------|
| **插件化架构** | 所有功能模块均为独立插件，核心不感知业务逻辑。 |
| **按需加载** | 通过全局配置文件控制插件启用/停用，未启用插件不加载。 |
| **故障隔离** | 单个插件加载失败不影响主框架运行，仅记录错误日志。 |
| **双因素认证** | 用户登录支持 **密码** 和 **密码+TOTP** 两种模式。 |
| **管理界面** | 提供左右分栏 Web 管理界面，菜单可折叠/展开，内容区带统一返回按钮。 |
| **统一通知管理** | 内置通知管理模块，支持邮件、企业微信、钉钉、飞书等渠道，提供统一 API 供插件调用，支持消息模板（Go template 语法）。 |
| **通用加密模块** | 提供独立的加密工具模块，支持 AES-256-GCM 等算法，供框架内部及插件调用。 |
| **配置安全** | 核心配置文件**只读**，不存在时自动生成默认配置；敏感信息加密存储；加密密钥存放于核心配置。 |
| **状态可视** | Web 看板动态显示所有插件的加载状态及元信息。 |
| **模块独立配置** | 每个插件拥有自己的配置目录，与全局配置隔离。 |
| **菜单动态注册** | 插件可向框架注册一级/二级菜单，自动出现在左侧菜单栏。 |
| **系统菜单可折叠** | 系统菜单提供折叠按钮，用户可按需隐藏以扩展内容区空间。 |
| **零数据库** | 所有持久化数据存储在配置文件中，不使用任何外部数据库。 |
| **热重启插件** | Web 后台支持单选/多选/批量热重启插件，无需停服，支持优雅关闭。 |
| **安全防护** | 支持 IP 黑白名单、会话超时管理、审计日志。 |
| **文档内置** | 框架自带 `wiki/` 文件夹，存放所有使用文档，方便非开发人员查阅。 |
| **响应式设计** | Web 管理界面必须适配常用手机和电脑分辨率。 |
| **便携部署** | 最终交付为单个可执行文件，客户无需安装 Python 或任何依赖，复制即用。 |
| **中文注释** | 所有 Python 源代码、YAML 配置文件、Shell 脚本、Vue 前端源码均须使用**中文注释**。 |

### 1.3 设计理念

- **完全解耦**：底层框架与插件之间仅通过标准接口通信，插件内部的任何错误均被框架捕获，不影响核心进程。
- **约定优于配置**：插件目录结构、入口文件命名等有明确约定，降低配置复杂度。
- **用户友好**：管理界面提供直观的菜单操作、状态反馈和配置指引；登录页显示上次登录信息；代码和配置均有中文注释，便于二次开发和维护。
- **安全优先**：密码初始提示但不强制修改、凭证加密传输、敏感信息加密存储、完整的操作审计。
- **能力复用**：加密模块、通知模块作为核心基础设施，统一封装，避免各插件重复实现。
- **文档即代码**：框架内置完整文档，并提供空白插件模板便于开发。
- **响应式优先**：管理界面应针对常用手机（如 375px 宽）和电脑（如 1920px 宽）分辨率进行适配。
- **开箱即用**：使用 PyInstaller 打包为单个可执行文件，启动时自动提取所需资源，客户拿到文件即可运行；升级只需替换可执行文件。
- **禁用 Emoji**：所有代码、配置、日志及文档中禁止使用任何 Emoji 字符。

## 二、编码与注释规范

### 2.1 Python 代码注释要求

- **文件头注释**：每个 `.py` 文件开头必须包含模块用途说明，格式如下：
  ```python
  """
  config_loader.py - 全局配置加载模块
  
  功能：读取 YAML 配置文件，校验配置项合法性
  若配置文件不存在则自动生成默认配置
  """
  ```
- **函数/方法注释**：所有函数、类方法必须使用 docstring 说明功能、参数和返回值。
  ```python
  def load_config(config_path: str) -> dict:
      """
      加载指定路径的 YAML 配置文件
      
      参数:
          config_path: 配置文件的绝对路径
          
      返回:
          解析后的配置字典；若文件不存在返回空字典
          
      异常:
          yaml.YAMLError: 配置文件格式错误时抛出
      """
  ```
- **关键逻辑注释**：复杂逻辑、算法、正则表达式等必须在代码块上方添加注释，解释其目的和原理。
- **TODO/FIXME 标记**：未完成或有缺陷的代码需用中文标记，例如 `# TODO: 需补充异常处理`。

### 2.2 YAML 配置文件注释要求

- 每个配置项必须附带**行内中文注释**，说明其用途、可选值、默认值。
- 配置段落开头使用分隔线注释标明模块名称。

### 2.3 前端代码注释要求

- Vue 组件中的关键 data、methods、computed 属性须添加中文注释。
- Axios 封装的 API 方法须注释说明接口路径、参数和用途。
- CSS 中关键布局样式须注明作用区域。

### 2.4 Shell 脚本注释要求

- 每段逻辑块前添加注释说明其功能。
- 变量定义处添加中文注释说明变量用途。

```
                   │
┌──────────────────▼──────────────────────┐
│              核心框架层 (Core)            │
│  ┌─────────────────────────────────────┐ │
│  │     PluginManager (扫描/加载/热重启)  │ │
│  ├─────────────────────────────────────┤ │
│  │     NotifyManager (通知渠道管理)      │ │
│  ├─────────────────────────────────────┤ │
│  │     CryptoUtils (通用加密模块)        │ │
│  ├─────────────────────────────────────┤ │
│  │     AuditLogger (审计日志接口)        │ │
│  └─────────────────────────────────────┘ │
│  ┌──────────────┐ ┌──────────────┐       │
│  │ 配置加载器    │ │ 认证模块     │       │
```

## 五、配置文件规范

### 5.1 四配置文件设计 + 系统信息硬编码

| 配置文件 | 路径 | 权限 | 用途 |
|----------|------|------|------|
| **核心配置** | `<exe_dir>/config/core.yaml` | **只读** | 服务端口、JWT、日志、会话、加密密钥、通知频率限制 |
| **用户配置** | `<exe_dir>/config/user_config.yaml` | **可读写** | 密码哈希、TOTP密钥、插件关闭列表（disabled 黑名单）、系统名称/版本 |
| **安全配置** | `<exe_dir>/config/security.yaml` | **可读写** | IP黑白名单、登录失败策略 |
| **通知配置** | `<exe_dir>/config/notify.yaml` | **可读写** | 邮件、企业微信、钉钉、飞书等通知渠道配置及消息模板 |

`<exe_dir>` 为可执行文件所在目录。若目录无写入权限，程序启动时检查并报错退出。

**系统名称与版本的处理**：
- 硬编码在程序代码中（默认值：`NetCore Framework` / `20260707-v6`）。
- 若 `user_config.yaml` 中存在 `system.name` 和 `system.version` 且非空，则使用它们覆盖默认值。
- 若用户配置中未定义或值为空，则使用硬编码的默认值。

### 5.2 `core.yaml` 详细定义（不可修改，自动生成）

```yaml
# ============================================================
# NetCore Framework 核心配置文件
# 此文件只读，修改需重启服务生效
# 若文件不存在，框架启动时自动生成
# ============================================================

# ---------- 服务配置 ----------
server:
  host: "0.0.0.0"          # 监听地址，0.0.0.0 表示监听所有网卡
  port: 8080               # 监听端口号
  debug: false             # 调试模式，生产环境必须设为 false

# ---------- 加密密钥 ----------
crypto:
  encryption_key: ""       # AES-256-GCM 加密密钥（Base64编码），首次启动自动生成，用于敏感配置加密存储

# ---------- JWT 认证配置 ----------
jwt:
  secret_key: ""           # JWT 签名密钥，每次启动自动生成随机字符串
  expire_minutes: 1440     # Token 有效期（分钟），默认 24 小时

# ---------- 日志配置 ----------
logging:
  level: "INFO"            # 日志级别：DEBUG / INFO / WARNING / ERROR
  file: "data/logs/"       # 日志目录（仅作路径说明），实际按天写入 {日期}-netcore.log
  max_bytes: 10485760      # 单文件最大字节数（10MB）
  backup_count: 30         # 保留最近日志文件个数
  audit_log_retention_days: 60   # 审计日志保留天数，过期自动清理

# ---------- Web 会话配置 ----------
# 空闲超时（自动退出）配置已迁移至 user_config.yaml 的 system.auto_logout_minutes，
# 由「系统设置-基础设置」界面维护，core.yaml 不再承载该参数。

# ---------- 通知频率限制 ----------
notify:
  rate_limit:
    enabled: true           # 是否启用通知发送频率限制
    min_interval_seconds: 60  # 同一渠道两次发送之间最小间隔（秒），默认 60 秒
```

### 5.3 `user_config.yaml` 详细定义（可读写）

```yaml
# ============================================================
# 用户配置文件（可读写）
# 此文件由框架自动维护，手工修改时请遵循格式规范
# 启用/禁用插件请在 Web 后台「系统管理-插件列表」操作（或调 toggle 接口），修改后自动重新加载插件
# ============================================================

# ---------- 系统信息（可选） ----------
system:
  name: ""                # 自定义软件名称（空则使用内置默认值）
  version: ""             # 自定义版本号（空则使用内置默认值）

# ---------- 认证相关 ----------
auth:
  # 管理员用户名（固定为 admin，暂不支持多用户）
  username: "admin"

  # 密码哈希值（PBKDF2-SHA256 算法，迭代次数 600000）
  # 如需重置密码，请添加 password_plain 字段并重启程序
  password_hash: "pbkdf2_sha256$600000$..."

  # TOTP 双因素认证开关
  totp_enabled: false
  # TOTP 密钥（Base32 编码，由框架在绑定时自动写入）
  totp_secret: ""

# ---------- 插件配置（黑名单语义） ----------
plugins:
  detected: ["netconfig_guardian", "wiki_docs"]   # 每次启动自动重新扫描 plugins/ 并写入「所有检测到的插件」（仅作记录，不参与启停判定）
  disabled: []                                      # 关闭列表（黑名单）：为空表示启用全部已发现插件；
  #   - wiki_docs                                  # 将插件名加入此列表即可停用该插件（wiki 插件默认启用）
  #   - another_plugin
```

> 插件采用**黑名单**语义：`plugins.disabled` 为空 `[]` 时启用全部已发现插件；把插件名写入该列表即停用。`wiki` 插件（实际插件名是 `wiki_docs`）默认不在 `disabled` 中，因此**默认启用**。旧版本的 `plugins.enabled` 白名单字段已废弃。

### 5.5 `notify.yaml` 详细定义（可读写，敏感信息加密存储）

```yaml
# ============================================================
# 通知管理配置（可读写）
# 密码、Webhook URL 等敏感字段使用 AES-256-GCM 加密存储
# 修改后立即生效（无需重启），也可通过 Web 后台管理
# ============================================================

# 全局模板：可被各渠道引用
templates:
  default: |
    {{if eq .Priority "high"}}[紧急] {{end}}{{.Title}}
    时间：{{.Time}}
    来源：{{.Source}}
    {{.Content}}
  alert: |
    **告警通知**
    > 优先级：{{.Priority}}
    > 时间：{{.Time}}
    > 来源：{{.Source}}
    {{.Content}}
  info: |
    信息通知：{{.Title}}
    {{.Content}}

# ---------- 邮件渠道 ----------
email:
  enabled: false
  smtp_host: ""                     # SMTP 服务器地址
  smtp_port: 465                    # 端口（465 SSL / 587 STARTTLS）
  smtp_ssl: true
```

## 六、加密模块规范

### 6.1 模块位置与作用
- 文件：`core/crypto_utils.py`
- 提供统一的加密解密、密码哈希功能，框架内部及所有插件均可直接调用。
- 加密密钥在 `core.yaml` 的 `crypto.encryption_key` 字段中存储（Base64 编码），首次启动自动生成。

### 6.2 公共接口定义

```python
class CryptoUtils:
    """通用加密工具类 - 框架及插件均可调用"""

    @staticmethod
    def generate_key() -> str:
        """生成随机 AES-256 密钥，返回 Base64 编码字符串"""
        ...

    @staticmethod
    def encrypt(plaintext: str, key: str) -> str:
        """使用 AES-256-GCM 加密明文，返回 Base64 密文（包含 nonce 和 tag）"""
        ...

    @staticmethod
    def decrypt(ciphertext: str, key: str) -> str:
        """解密 AES-256-GCM 密文，返回明文字符串"""
        ...

    @staticmethod
    def hash_password(password: str) -> str:
        """使用 PBKDF2-SHA256 生成密码哈希"""
        ...

    @staticmethod
    def verify_password(password: str, password_hash: str) -> bool:
        """验证密码与哈希是否匹配"""
        ...
```

### 6.3 插件调用示例

```python
from core.crypto_utils import CryptoUtils
from core.config_loader import get_core_config

# 获取加密密钥
key = get_core_config()["crypto"]["encryption_key"]

# 加密
encrypted = CryptoUtils.encrypt("敏感数据", key)

# 解密
plain = CryptoUtils.decrypt(encrypted, key)
```

### 6.4 通知配置加密存储机制
- 当通过 Web 界面或 API 保存通知配置时，密码、Webhook URL、加签密钥等敏感字段先使用 `CryptoUtils.encrypt()` 加密，再写入 `notify.yaml`。
- 读取时，框架自动解密后提供给通知渠道。
- **保存时若某个敏感字段值为空（或加密后为空），视为不更新该字段**，保留原值不变。

### 7.2 插件基类接口

```python
from abc import ABC, abstractmethod
from typing import Optional, List, Dict
from fastapi import APIRouter

class BasePlugin(ABC):
    def __init__(self, name: str, config: dict = None):
        self.name = name
        self.config = config or {}
        self._loaded = False

    @abstractmethod
    def get_metadata(self) -> Dict[str, str]:
        """返回插件元信息（名称、版本、描述、作者）"""
        pass

    @abstractmethod
    def on_load(self) -> bool:
        """加载插件，返回 True/False"""
        pass

    @abstractmethod
    def get_routes(self) -> Optional[APIRouter]:
        """注册 API 路由，返回 APIRouter 或 None"""
        pass

    @abstractmethod
    def get_menus(self) -> List[Dict]:
        """注册菜单项"""
        pass

    def on_unload(self):
        """优雅关闭，最长等待 10 秒"""
        pass
```

```python
from core.audit import audit_log

# 参数说明：
# action  - 操作类型字符串，建议使用小写加下划线命名，如 "device_backup"、"config_diff"
# detail  - 操作详情字符串，可包含附加信息，如 "设备 192.168.1.1 配置已变更"

audit_log(
    action="device_backup",
    detail="设备 huawei-core-01 (10.0.0.1) 配置采集成功",
    result="success"
)
```

- 该接口会自动记录时间戳（UTC）、来源 IP（若从请求上下文获取）、用户名等标准字段。

- 所有审计日志条目均统一写入 `data/logs/audit/` 目录下的 JSONL 文件，遵循主框架的保留策略。

## 八、认证模块规范

### 8.1 用户管理
- 内置管理员 `admin`，初始密码 `Admin@123!`。
- 首次登录生成 PBKDF2-SHA256 哈希保存。
- 默认密码登录后页面显示提示条，但不强制修改。

### 8.2 登录流程
1. 前端收集用户名、密码以及 TOTP 验证码（若已绑定）。
2. 用户提交凭证（密码和 TOTP 均为 AES-256-GCM 加密传输）。
3. 后端解密校验，含 TOTP 二次认证。
4. 签发 JWT，记录审计日志。

### 8.3 TOTP 绑定
- 提供 Base32 密钥和二维码，密钥等宽字体显示，可复制。

### 8.4 JWT Token
- 每次启动重新生成签名密钥，旧 Token 失效。
- 当前仅支持单实例。

### 8.5 密码重置
- 在 `user_config.yaml` 添加 `password_plain`，重启后自动加密并退出。

### 12.4 插件集成接口

框架核心向插件暴露一个 Python 函数接口，用于写入审计日志条目，接口位于 `core/audit.py` 模块。

#### 函数签名

```python
def audit_log(action: str, detail: str = "", result: str = "success", username: str = None):
    """
    写入一条审计日志记录。

    参数:
        action:   操作类型，如 "device_backup"、"config_change"、"notify_test" 等。
        detail:   操作详情，可包含设备 IP、配置差异摘要等自由文本。
        result:   操作结果，可选 "success" 或 "failed"。
        username: 操作人，默认 None。若为 None 且当前存在 HTTP 请求上下文，
                  则自动提取已认证用户名；否则使用 "system"。
    """
```

#### 行为说明
- 自动填充 `timestamp_utc`（当前 UTC 时间）。
- 自动填充 `ip`：若在 HTTP 请求上下文中，取客户端 IP；否则填 `"127.0.0.1"`。
- 写入目标为当天的审计日志文件 `data/logs/audit/audit-YYYYMMDD.log`。
- 该函数是线程安全的，插件可在任意上下文中直接调用。

#### 调用示例（插件内）

```python
from core.audit import audit_log

# 记录配置变更
audit_log(
    action="config_change",
    detail="设备 h3c-switch-02 检测到配置变更，变更行数: 5",
    result="success"
)
```

该接口使得所有插件的行为都可以被纳入框架的统一审计体系，无需各自实现日志持久化。

| P2 | 一般 | UI 错位、返回按钮失效 |
| P3 | 轻微 | 提示语不清晰 |

## 附录 E：通知渠道接口规范

### 发送请求
```json
POST /api/notify/send
{
  "channels": ["email", "dingtalk"],
  "title": "磁盘告警",
  "content": "服务器 /data 分区使用率达到 90%",
  "priority": "high",
  "recipients": ["admin@example.com"],
  "template_id": "alert",
  "template_vars": {
    "host": "192.168.1.100",
    "usage": "90%"
  }
}
```

### 响应示例
```json
{
  "results": [
    {"channel": "email", "success": true, "message": "已发送"},
    {"channel": "dingtalk", "success": false, "message": "Webhook 超时"}
  ]
}
```

### 渠道状态
```json
GET /api/notify/channels
{
  "channels": [
    {"id": "email", "name": "邮件", "enabled": true, "status": "active"},
    {"id": "dingtalk", "name": "钉钉", "enabled": false, "status": "disabled"}
  ]
}
```

### 测试渠道
```json
POST /api/notify/test/email
{
  "recipients": "test@example.com"
}
返回：{"success": true, "message": "测试邮件已发送"}
```
