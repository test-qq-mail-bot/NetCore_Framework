## 一、架构概述

### 1.1 插件化设计理念

NetCore Framework 采用**微核心 + 插件化**架构：

```
+----------------------------------------------------------+
|                   Web 前端 (Vue3 + Element Plus)            |
|              左侧可折叠菜单栏 / 右侧内容区                    |
+---------------------------+------------------------------+
                            | HTTP API (JWT 认证 + AES 加密)
+---------------------------v------------------------------+
|                  FastAPI 路由层                           |
|   核心路由 (/api/auth, /api/system, ...)                   |
|   + 插件路由 (由各插件通过 get_routes() 注册)               |
+---------------------------+------------------------------+
                            |
+---------------------------v------------------------------+
|                   核心框架层 (core/)                        |
|  CryptoUtils | AuditLogger | NotifyManager | PluginManager |
|  ConfigLoader | SecurityManager | SessionManager            |
+---------------------------+------------------------------+
                            |
+---------------------------v------------------------------+
|                     插件层 (plugins/)                      |
|  netconfig_guardian/  |  your_plugin/  |  ...             |
+----------------------------------------------------------+
```

**关键原则**：
- 框架**不感知**业务逻辑，所有功能以插件形式接入
- 插件内部错误被框架捕获，**不影响主进程运行**
- 插件之间完全隔离，通过框架统一接口通信
- 热重启：可在 Web 后台动态卸载/重新加载插件，无需停服

### 1.2 插件生命周期

```
[发现] -> [加载 on_load()] -> [挂载路由] -> [注册菜单] -> [服务中]
                                                          |
                                              [热重启 / 卸载]
                                                          |
                                             [on_unload() -> 优雅关闭]
```

## 二、插件目录结构

每个插件是 `plugins/` 下的一个独立目录：

```
plugins/
└── <plugin_name>/           # 插件标识名（目录名），如 netconfig_guardian
    ├── __init__.py          # 包初始化文件（可为空）
    ├── plugin.py            # 【必须】插件入口，继承 BasePlugin
    ├── config/
    │   └── config.yaml      # 插件私有配置（可选）
    ├── requirements.txt     # Python 依赖列表（可选）
    ├── data/                # 运行时数据（自动创建）
    │   ├── xxx.db           # SQLite 数据库等
    │   └── backups/         # 业务数据文件
    ├── logs/                # 插件本地日志（自动创建）
    │   └── plugin.log
    └── drivers/             # 业务模块（按需）
        ├── huawei.py
        └── cisco.py
```

**命名约定**：
- 目录名使用**小写下划线**：`netconfig_guardian`（不是 camelCase 或连字符）
- `plugin.py` 是固定入口文件名，不可改名
- 所有 `.py` 文件必须有中文注释

## 三、BasePlugin 基类接口（完整）

源码位置：`plugins/base_plugin.py`

```python
from abc import ABC, abstractmethod
from typing import Dict, List, Optional
from fastapi import APIRouter


class BasePlugin(ABC):
    """插件基类，所有业务插件需继承并实现抽象方法"""

    def __init__(self, name: str, config: dict = None):
        """
        初始化插件实例（由框架在发现插件时自动调用）

        参数:
            name: 插件标识名（即目录名）
            config: 从 config/config.yaml 解析的配置字典，若配置文件不存在则为空字典 {}
        """
        self.name = name
        self.config = config or {}
        self._loaded = False

    @abstractmethod
    def get_metadata(self) -> Dict[str, str]:
        """
        返回插件元信息

        返回格式:
            {
                "name": "插件标识",       # 应与目录名一致
                "version": "1.0.0",      # 语义化版本号
                "description": "描述文字",
                "author": "作者名称"
            }
        """
        pass

    @abstractmethod
    def on_load(self) -> bool:
        """
        加载插件（框架启动或热重启时调用）

        在此方法中完成：
          - 初始化数据库连接/建表
          - 读取并合并配置
          - 启动后台任务/定时调度器
          - 加载驱动或外部依赖

        返回:
            True  -> 加载成功，框架继续挂载路由和菜单
            False -> 加载失败，框架记录错误但不影响其他插件
        """
        pass

    @abstractmethod
    def get_routes(self) -> Optional[APIRouter]:
        """
        注册插件专属的 API 路由

        返回:
            FastAPI APIRouter 实例，包含该插件的所有 HTTP 接口
            若返回 None，则该插件不注册任何路由（仅做后台任务等）
        """
        pass

    @abstractmethod
    def get_menus(self) -> List[Dict]:
        """
        注册前端菜单项（显示在左侧菜单栏的"插件菜单区"）

        返回:
            菜单数组，支持一级和二级菜单（见下方数据结构说明）
        """
        pass

    def on_unload(self):
        """
        优雅关闭（热重启或程序退出时由框架调用，非必须覆写）

        注意事项:
            - 框架会控制最长等待时间（约10秒）
            - 在此方法中停止后台线程、关闭数据库连接、释放资源
            - 不要在此方法中执行耗时操作
        """
        pass
```

## 四、开发流程（Step by Step）

### 第一步：创建目录结构

```bash
cd /path/to/netcore-framework/plugins
mkdir -p my_plugin/config my_plugin/data my_plugin/logs
```

### 第二步：编写 plugin.py 入口

最小可用示例：

```python
"""
plugins/my_plugin/plugin.py - 我的插件

功能：演示插件开发的最低要求
"""
from typing import Dict, List, Optional
from fastapi import APIRouter

from plugins.base_plugin import BasePlugin
from core.auth import get_current_user


class MyPlugin(BasePlugin):
    """我的插件"""

    def get_metadata(self) -> Dict[str, str]:
        return {
            "name": "my_plugin",
            "version": "1.0.0",
            "description": "这是一个示例插件",
            "author": "Developer Name"
        }

    def on_load(self) -> bool:
        # 初始化逻辑：建表、读配置、启服务等
        return True

    def get_routes(self) -> Optional[APIRouter]:
        router = APIRouter(prefix="/api/my_plugin")

        @router.get("/hello")
        async def hello(_: str = Depends(get_current_user)):
            return {"message": "Hello from MyPlugin!", "status": "ok"}

        return router

    def get_menus(self) -> List[Dict]:
        return [{
            "id": "my_plugin",
            "label": "我的插件",
            "icon": "guardian",
            "children": [
                {"id": "mp_home", "label": "首页", "path": "/my_plugin"}
            ]
        }]
```

### 第三步：（可选）创建插件配置 config.yaml

```yaml
# plugins/my_plugin/config/config.yaml
# 插件私有配置（Web 后台可读写）

# 功能开关
enabled: true

# 业务参数
max_items: 100
timeout_seconds: 30
```

> 配置文件会被框架自动读取并通过 `self.config` 传递给 `__init__()`。

### 第四步：（可选）声明依赖 requirements.txt

```
# plugins/my_plugin/requirements.txt
requests>=2.28.0
```

> 注意：打包为单文件 exe 时，需要在 `build.spec` 的 `hiddenimports` 中添加这些依赖对应的模块。

## 五、调用框架核心能力

### 5.1 加密模块 CryptoUtils

用于敏感数据的加密存储和解密读取。

```python
from core.crypto_utils import CryptoUtils
from core.config_loader import get_core_config

# ---- 获取加密密钥（来自 core.yaml）----
key = get_core_config()["crypto"]["encryption_key"]

# ---- 加密 ----
ciphertext = CryptoUtils.encrypt("明文敏感数据", key)
# 返回: Base64 编码字符串（含 12 字节 nonce + 密文 + GCM tag）

# ---- 解密 ----
plaintext = CryptoUtils.decrypt(ciphertext, key)
# 返回: 原始明文字符串

# ---- 密码哈希（用于存储用户密码）----
password_hash = CryptoUtils.hash_password("Admin@123!")
# 格式: "pbkdf2_sha256$600000$base64salt$base64hash"

# ---- 验证密码 ----
is_valid = CryptoUtils.verify_password("输入密码", stored_hash)
# 返回: True / False
```

**典型用途**：
- 存储设备登录密码（如数通卫士插件中的 credential 字段）
- 存储 SSH 私钥
- 存储第三方服务的 Token/Secret

### 5.2 审计日志 audit_log

将插件的关键操作写入框架统一的审计日志系统。

```python
from core.audit import audit_log

# ---- 写入审计日志 ----
audit_log(
    action="device_add",              # 操作类型（建议 小写英文_下划线）
    detail="添加设备: router01 (192.168.1.1)",  # 操作详情（自由文本）
    result="success",                 # 结果："success" 或 "failed"（默认 success）
    username="admin"                  # 操作人（可选；不传则自动从请求上下文获取）
)

# ---- 后台任务中写入（无HTTP请求上下文时）----
audit_log(
    action="config_change_detected",
    detail="设备 switch02 发现配置变更，变更行数: 5",
    result="success",
    username="system"                 # 后台任务显式传入
)
```

**行为说明**：
- 自动填充 `timestamp_utc`（当前 UTC 时间）、`ip`（客户端 IP 或 127.0.0.1）
- 日志写入 `data/logs/audit/audit-YYYYMMDD.log`（JSONL 格式）
- 线程安全，可在任意上下文中调用
- 保留策略遵循 `core.yaml` 中 `audit_log_retention_days` 配置（默认 60 天）

**action 命名建议**：前缀为插件简称或功能域，避免与核心冲突。

### 5.3 通知发送

#### 方式 A：HTTP 调用（推荐，解耦最彻底）

```python
import httpx

async def send_alert(title, content):
    """通过框架通知 API 发送告警"""
    async with httpx.AsyncClient() as client:
        resp = await client.post(
            "http://localhost:8080/api/notify/send",
            json={
                "channels": ["email", "dingtalk"],
                "title": title,
                "content": content,
                "priority": "high",
                "recipients": ["admin@example.com"],
                "template_id": "alert",
                "template_vars": {"host": "192.168.1.1"}
            },
            headers={"Authorization": "Bearer <JWT_TOKEN>"}
        )
        return resp.json()
```

#### 方式 B：直接导入 NotifyManager（需要获取有效 Token）

```python
from core.notify import get_notify_manager

mgr = get_notify_manager()
results = mgr.send(
    channels=["email"],
    title="设备告警",
    content="router01 连接失败",
    priority="high",
    recipients=["admin@example.com"],
    source="netconfig_guardian"
)
# results: [{"channel": "email", "success": True, "message": "..."}]
```

## 六、菜单注册规范

### 6.1 数据结构

```json
[
  {
    "id": "unique_menu_id",
    "label": "一级菜单名称",
    "icon": "guardian",
    "children": [
      { "id": "sub_id_1", "label": "子菜单A", "path": "/plugin/page-a" },
      { "id": "sub_id_2", "label": "子菜单B", "path": "/plugin/page-b" }
    ]
  }
]
```

### 6.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 全局唯一标识（用于 CSS/JS 定位） |
| `label` | string | 是 | 显示文本（中文） |
| `icon` | string | 否 | 内置 SVG 图标名（非 emoji），可选值：`dashboard`(概览)、`setting`(设置)、`security`(盾牌)、`bell`(铃铛)、`log`(文档/日志)、`plugin`(拼图)、`guardian`(脉冲)、`doc`(文档)。留空则使用默认图标 |
| `path` | string | 子菜单必填 | Vue Router 路径，点击后地址栏变为该路径 |
| `children` | array | 否 | 子菜单数组；有 children 则为折叠式一级菜单 |

### 6.3 菜单渲染规则

- 一级菜单**带子菜单**：显示为可展开组，点击一级标题无跳转
- 一级菜单**不带子菜单**（直接有 path）：点击直接导航到 path
- 子菜单：总是带 path，点击导航
- 菜单位于左侧栏的**下半部分**（上半部分是系统菜单：概览/设置等）
- 菜单图标为内置线性 **SVG**（由 `icon` 字段指定），**非 emoji**；侧边栏展开时显示「图标 + 文字」，折叠时仅显示图标。
- 默认仅展示一级菜单；点击带子菜单的一级菜单会在其下方展开/收起二级（支持任意层级），点击叶子菜单才进入页面。

### 6.4 完整示例

```python
def get_menus(self) -> List[Dict]:
    return [{
        "id": "my_business_plugin",
        "label": "业务插件",
        "icon": "guardian",

            {"id": "bp_list", "label": "数据列表", "path": "/my_plugin/list"},
            {"id": "bp_settings", "label": "插件设置", "path": "/my_plugin/settings"},
```

## 七、API 路由开发规范

### 7.1 路由注册方式

```python
def get_routes(self) -> Optional[APIRouter]:
    # 使用 prefix 统一加前缀，避免与其他插件冲突
    router = APIRouter(prefix="/api/my_plugin")

    # 所有接口都需要 JWT 认证（Depends(get_current_user)）
    @router.get("/items")
    async def list_items(_: str = Depends(get_current_user)):
        return {"items": [...]}

    @router.post("/items")
    async def create_item(req: dict, _: str = Depends(get_current_user)):
        # req 为 JSON 请求体（dict）
        return {"success": True, "id": 123}

    return router
```

### 7.2 认证机制

所有插件 API 必须添加认证依赖：

```python
from core.auth import get_current_user

@router.get("/data")
async def get_data(current_user: str = Depends(get_current_user)):
    # current_user 当前始终为 "admin"（框架暂不支持多用户）
    # 若未登录或 Token 无效，FastAPI 自动返回 401
    ...
```

### 7.3 请求/响应约定

**POST/PUT 请求体**：JSON 格式，无需定义 Pydantic Model（可直接用 `req: dict`）

**标准成功响应**：
```json
{"success": true}
{"success": true, "id": 123}
{"items": [...], "total": 42}
```

**分页响应**（GET 列表接口推荐）：
```json
{
  "devices": [...],
  "total": 42,
  "page": 1,
  "size": 20
}
```

**错误响应**：
```json
{"success": false, "message": "错误原因说明"}
```

### 7.4 文件下载

```python
from fastapi.responses import FileResponse
from pathlib import Path

@router.get("/files/{file_id}/download")
async def download_file(file_id: int, _: str = Depends(get_current_user)):
    file_path = Path("/path/to/file.txt")
    if not file_path.exists():
        return JSONResponse(status_code=404, content={"detail": "文件不存在"})
    return FileResponse(file_path, filename="download.txt")
```

## 八、前端页面开发规范

### 8.1 技术栈

NetCore Framework 前端采用**纯静态单页应用**（SPA），技术栈：
- **Vue 3**（全局 CDN 引入，UMD 版本）
- **Element Plus**（UI 组件库）
- **Axios**（HTTP 客户端）
- **AES-256-GCM** 加密传输（`aesgcm.js` 纯 JS 实现）

> 前端代码位于 `frontend/app.js`，所有页面组件定义为 JavaScript 对象。

### 8.2 添加新页面

在 `frontend/app.js` 中定义新的页面组件：

```javascript
/* ===================== 我的插件：首页 ===================== */
const MyPluginDashboard = {
    template: `
    <div class="nc-card">
      <h3>我的插件 - 仪表盘</h3>
      <p>这里放置你的插件界面内容</p>
      <el-table :data="rows" border>
        <el-table-column prop="name" label="名称"></el-table-column>
        <el-table-column prop="value" label="值"></el-table-column>
      </el-table>
    </div>`,
    data() { return { rows: [] }; },
    methods: {
        async load() {
            const r = await http.get('/api/my_plugin/items');
            this.rows = r.data.items || [];
        }
    },
    mounted() { this.load(); }
};
```

### 8.3 注册页面组件

**步骤 1**：将组件加入根组件的 `components` 列表：

```javascript
// 在 App 对象的 components 中添加：

    // ... 已有组件
    MyPluginDashboard,   // 新增
},
```

**步骤 2**：在路径映射表中添加路由：

```javascript
function resolveComponent(path) {
    // ... 已有映射
    const map = {
        // ... 已有映射
        '/my_plugin': 'MyPluginDashboard',    // 新增
        '/my_plugin/dashboard': 'MyPluginDashboard',

    // ...
}
```

### 8.5 Axios 封装

框架已全局创建 axios 实例 `http`，已配置：
- 自动携带 JWT Token（`Authorization: Bearer xxx`）
- 401 响应自动跳转登录页

直接使用：
```javascript
const r = await http.get('/api/my_plugin/data');   // GET
const r = await http.post('/api/my_plugin/data', body);  // POST
const r = await http.put('/api/my_plugin/data/1', body);  // PUT
```

## 九、配置文件管理

### 9.1 插件私有配置

配置文件路径：`plugins/<name>/config/config.yaml`（推荐）

框架在加载插件时**自动读取**此文件并将内容传入 `__init__(self, name, config)` 的 `config` 参数。

查找顺序（`core/plugin_manager.py` 的 `_load_plugin_config`）：

1. `plugins/<name>/config/config.yaml` —— 推荐位置；
2. `plugins/<name>/config.yaml` —— 兼容把配置直接放在插件根目录的写法；

两处都不存在时 `config` 为空字典 `{}`，插件需自行使用内置默认值。**同名配置只会命中第一个存在的文件**，请不要两处都放，否则根目录那份不会生效。

### 9.2 运行时修改与持久化

插件可以在 Web API 中提供设置接口，手动写回 YAML：

```python
import yaml
from pathlib import Path
from core.config_loader import PLUGINS_DIR

@router.put("/settings")
async def put_settings(req: dict, _: str = Depends(get_current_user)):
    # 合并配置
    for k in self.DEFAULT_SETTINGS:
        if k in req:
            self.settings[k] = req[k]

    # 持久化到磁盘
    cfg_path = PLUGINS_DIR / "my_plugin" / "config" / "config.yaml"
    with open(cfg_path, "w", encoding="utf-8") as f:
        yaml.safe_dump(self.settings, f, allow_unicode=True, sort_keys=False)

    return {"success": True}
```

## 十、数据持久化方案

### 10.1 推荐 SQLite

框架自身零数据库（配置均为 YAML），但插件可以自由选择存储方案。

**推荐使用 SQLite**（Python 内置，轻量可靠）：

```python
import sqlite3
from pathlib import Path

# 数据库路径建议放在插件 data/ 目录下
DB_PATH = PLUGINS_DIR / "my_plugin" / "data" / "my_plugin.db"

def init_db():
    """首次运行时建表"""
    DB_PATH.parent.mkdir(parents=True, exist_ok=True)
    conn = sqlite3.connect(str(DB_PATH))
    conn.execute("""
        CREATE TABLE IF NOT EXISTS items (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            name TEXT NOT NULL,
            value TEXT,
            created_at TEXT DEFAULT (datetime('now')),
            updated_at TEXT DEFAULT (datetime('now'))
        )
    """)
    conn.commit()
    conn.close()

def create_item(data: dict) -> int:
    conn = sqlite3.connect(str(DB_PATH))
    cur = conn.execute(
        "INSERT INTO items (name, value) VALUES (?, ?)",
        (data["name"], data.get("value", ""))
    )
    conn.commit()
    item_id = cur.lastrowid
    conn.close()
    return item_id
```

> **注意**：SQLite 是 PyInstaller 打包时的隐式依赖。如果插件使用了 `sqlite3`，
> 务必确保 `build.spec` 的 `hiddenimports` 包含 `"sqlite3"`。

### 10.2 文件存储

适用于大文本、二进制数据（如配置备份原文）：

```python
from pathlib import Path
import datetime

BACKUP_DIR = PLUGINS_DIR / "my_plugin" / "data" / "backups"

def save_backup(device_id: int, content: str) -> Path:
    device_dir = BACKUP_DIR / str(device_id)
    device_dir.mkdir(parents=True, exist_ok=True)
    ts = datetime.datetime.now().strftime("%Y%m%d-%H%M%S")
    file_path = device_dir / ("%s.cfg" % ts)
    file_path.write_text(content, encoding="utf-8")
    return file_path
```

> **v31 异步/线程化说明（重要）**：数通卫士所有涉及设备连接（SSH/netmiko）、SNMP、文件读写的接口（`test`、`batch-action` 各 action、`snmp-query`、`logs`、`live-info`、`refresh-info` 等），以及框架核心的通知发送/测试、插件重载接口，均已改为 `await asyncio.to_thread(...)` 执行——阻塞 I/O 在 worker 线程运行，**绝不阻塞 asyncio 事件循环**。其中 `batch-action` 多台设备以 `asyncio.Semaphore(max_concurrent_devices)` 并发执行（`max_concurrent_devices` 默认 20，见插件设置）。因此任一模块的耗时操作都不会导致其他模块卡死，前端「多选批量获取配置」时其余界面仍可正常点击。前端契约（请求/响应字段）保持不变。
>
> **v32 连接状态 / 设备信息 / 任务自动取消（6 项需求）**：
> - **连接状态实时**：列表「连接状态」列中文化 `green→正常` / `red→失败` / 无→`未知`；事件驱动置位——点击「测试」不可用立即 `red`、定期任务设备采集成功立即 `green`（`engine.run_task` 成功分支）、其余按设备「自动检测间隔」(`auto_check_interval`) 周期更新（不依赖前端轮询）。
> - **下载缓存配置**：`GET /latest-config` 通过 `Content-Disposition: filename*=UTF-8''`（RFC5987）下发中文名 `设备名称-缓存日期_时间.cfg`；「获取最新配置」走 `batch-action collect` 直接写软件缓存。
> - **实时设备信息**：`POST /devices/{id}/live-info` 连设备按厂商命令表（华为 `display version`、思科 `show version` 等 7 类）采集并 `upsert_device_info`；详情页按钮已改名「点击更新设备信息」。
> - **编辑设备 500 修复**：`db.update_device` 中 `sqlite3.Row` 误用 `.get()` 改为 `["..."]`，修复「编辑 SNMP 等任意编辑 PUT 500」。
> - **任务全选**：新建/编辑任务对话框设备选择加「全选」「清空」按钮（一键设 `device_ids` 为全部 / 清空）。
> - **任务自动取消条件**：`tasks` 表加 `max_executions` / `max_consecutive_failures`（默认 0=不开启）+ 计数 `execution_count` / `consecutive_failure_count`；新建任务折叠「自动取消条件」含两数字输入；`engine.run_task` 达上限自动 `set_task_enabled(id,0)` 关闭任务并写 `task_auto_cancel` 日志。
>
> **v33 中文错误 / 无 emoji / 下载规范 / SNMP 双模式（7 项需求）**：
> - **中文错误**：`engine.translate_error(exc)` 把常见 netmiko/网络异常映射为中文，应用于 `backup_device` / `test_device` / `device_live_info` / 自动监测。
> - **去 emoji**：批量操作结果 `✅/❌` 改为文字 `成功：/失败：`；全项目 UI 已无 emoji。
> - **时间格式**：列表"最后采集"列经 `fmtTime()` 格式化为 `YYYY-MM-DD HH:MM:SS`。
> - **下载规范 + 内容保真**：备份列表行内"下载"（`GET /backups/{id}/download`）与"下载缓存设备配置"（`GET /latest-config`）均按 `设备名称-日期_时间.cfg` 下发 RFC5987 中文名；`drivers.parse_config` 保留行首缩进、跳过提示符行，下载配置与真机格式一致。
> - **设备信息正确性**：`collect_device_info` 补齐 `memory_total/memory_used/flash_total/flash_used`，前端移除会显示 `/` 的冗余项、改显 CPU/内存使用，并新增"原始采集数据"折叠区供核对。
> - **SNMP 双模式**：新增**完全独立**端点 `POST /devices/{id}/snmp-get` 与 `POST /devices/{id}/snmp-getnext`（各自只调自己的函数，互不牵连）；两者均"未填 community → 用设备已保存 SNMP，填了 → 用填写的"。前端 SNMP 页拆为 GET / GETNEXT 两独立子标签：`max_results` 默认 100 可自定义、空结果互提示切换、支持 CSV 下载与详情弹窗。

- `excludes`: 排除不需要的大型依赖（如 tkinter）

### 12.3 插件部署

**开发模式**：将插件目录放入 `plugins/` 下即可，重启生效。

**生产模式（exe）**：
1. 将插件目录放入 exe 同级 `plugins/` 目录
2. 重启程序或通过 Web 后台"热重启"
3. 框架会自动扫描、加载、挂载路由和菜单

### 12.4 调试技巧

1. **查看日志**：`data/logs/{日期}-netcore.log`（含启动信息与端口占用提示；不再生成根目录 `startup.log`）
2. **查看插件加载状态**：Web 后台 → 系统设置 → 插件管理
3. **测试 API**：浏览器 F12 开发者工具 Network 面板，或 curl

```bash
# 1. 先登录获取 Token
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"加密后","password":"加密后"}'

# 2. 使用 Token 调用插件 API
curl http://localhost:8080/api/my_plugin/hello \
  -H "Authorization: Bearer <TOKEN>"
```

## 十四、插件开发契约补充

### 14.1 路由映射机制（重要！）

页面 ID 与 URL 路径遵循命名约定，框架在 `app.js` 中通过 `resolvePageId()` **自动把 URL 路径推导为页面 ID**，无需手动维护映射表：

| 页面 ID | URL 路径 | 规则 |
|---------|----------|------|
| `guardian_devices` | `/guardian/devices` | `<插件名>_<页面名>` → `/<插件名>/<页面名>` |
| `opstoolbox_portscan` | `/opstoolbox/portscan` | 同上 |
| `cmdb_dashboard` | `/cmdb/dashboard` | 同上 |

**显式路径（仅约定推导失败的例外）**：在 `registerPage` 时传第 4 个参数：

```js
// 例外：页面 ID 为 cmdb_it，但 URL 路径是 /cmdb/it-assets
window.NC.registerPage('cmdb_it', { template: `...` }, 'IT 资产管理', '/cmdb/it-assets');
```

**框架核心页**（永远存在，由框架内建）：

| 路径 | 页面 ID |
|------|---------|
| `/dashboard` | `core_dashboard` |
| `/system/basic-settings` | `core_basic` |
| `/system/security` | `core_security` |
| `/system/notify` | `core_notify` |
| `/system/log-center` | `core_logs` |
| `/system/plugins` | `core_plugins` |

### 14.2 前端 manifest 机制

框架自动将 `plugins/<name>/frontend/` 挂载到 `/plugin-assets/<name>/`：

- `plugins/my_tool/frontend/home.js` → `http://127.0.0.1:8080/plugin-assets/my_tool/home.js`
- `/plugin-assets/*` **不鉴权**（公开访问），敏感数据请通过带 Bearer 的 API 端点提供
- 脚本清单通过 `GET /api/plugins/frontend-manifest` 提供，前端启动时自动注入：

```json
{ "files": [ "/plugin-assets/my_tool/home.js", "/plugin-assets/my_tool/settings.js" ] }
```

框架在 `app.js` 启动拉取此清单，动态创建 `<script>` 标签加载所有插件 JS；加载完成后各 JS 中 `NC.registerPage()` 已执行、页面 ID 已注册，路由即可正常跳转。

## 十五、常见问题（FAQ）

### Q1: 插件加载失败怎么办？

检查 `data/logs/{日期}-netcore.log` 中的错误信息。常见原因：
- `requirements.txt` 中的依赖未安装
- 缺少必要的 hiddenimports（打包时）
- `on_load()` 返回 False 或抛出异常

### Q2: 如何让插件在 Web 后台的菜单中显示？

确保 `get_menus()` 返回正确的菜单结构，且菜单 `children` 中的 `path` 与 `frontend/app.js` 中 `resolveComponent()` 的映射一致。

### Q3: 插件 API 返回 401 未认证？

确保每个路由函数都有 `_: str = Depends(get_current_user)` 参数。

### Q4: 如何加密存储敏感数据？

使用 `CryptoUtils.encrypt(plaintext, key)` 加密，`CryptoUtils.decrypt(ciphertext, key)` 解密。密钥从 `get_core_config()["crypto"]["encryption_key"]` 获取。

### Q5: 打包后 sqlite3 模块找不到？

在 `build.spec` 的 `hiddenimports` 中添加 `"sqlite3"`。

### Q6: 前端 crypto.subtle 报 undefined？

当通过局域网 IP（非 localhost/HTTPS）访问时，浏览器的 WebCrypto API 不可用。框架已在 `aesgcm.js` 中提供了纯 JS 回退实现，前端 `aesEncrypt()` 会自动降级。

### Q7: 默认端口 8080 被占用了怎么办？

框架会在控制台输出明确的端口冲突警告，并自动尝试 8081、8082... 直到找到可用端口（最多尝试 +20）。同时会将信息记录到主日志 `data/logs/{日期}-netcore.log`。

### Q8: 如何进行插件热重启？

Web 后台 → 系统设置 → 插件管理 → 点击"热重启"按钮。也可通过 API：
```bash
curl -X POST http://localhost:8080/api/system/plugins/reload \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"name": "your_plugin"}'
```

### Q9: 如何在 Web 后台启用/禁用插件？

Web 后台 → 系统设置 → 插件列表 → 每行「启用」列的开关联控件即可开关插件；开关状态持久化到 `user_config.yaml` 的 `plugins.disabled`（黑名单），并触发插件重新加载，侧边栏菜单随之更新。也可通过 API：
```bash
curl -X POST http://localhost:8080/api/plugins/netconfig_guardian/toggle \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"enabled": false}'
```
> 说明：`plugins.disabled` 为空表示启用全部已发现插件；写入具体列表（如 `["wiki_docs"]`）则仅停用列表内插件，其余照常加载。采用黑名单语义后，关闭全部插件不会再被误判为「全部启用」。
